# 공동 보상 상세 · P3 Page Record

> [SEED PROCESS](../seed/PROCESS.md) · [4유형](../seed/pages/page-types.md) · [21개 계약](../seed/INDEX.md). 웹 Preview는 픽션 데이터이며 실제 지급·가입/구매 저장을 구현하지 않는다.

## 01 Page Intent

| 필드 | 결정 |
|---|---|
| 유형 | 글로벌이너 (Standard+Back, 클랜 탭 유지) |
| 과업(동사) | 예정된 공동 보상 아이템과 획득 조건을 비교한다 |
| 목적 | 예정 보상 선택의 근거를 아이템별 이름과 조건으로 구체화한다 |
| 주연 1개 | O-ITEM 보상 미리보기 목록 |
| 대표 행동 1개 | 클랜 홈으로 돌아가기(기존 Back) |
| 핵심 데이터 | 아이템 이미지·이름·예정 조건, 공동 진행값 |
| 보조 데이터 | 상자 A1 미디어와 마감 |
| 다른 화면 책임 | 참여·응원→#clan, 멤버→#clan-my |
| 제외 목록과 이유 | 가격·소유·장착·구매·수령 완료 버튼과 A3 연출은 미확정/미지급 상태이므로 금지 |

**G1:** 주연 1개/대표 행동 1개/제외 목록 확보. 구현 후 첫 뷰포트 실측으로 재판정한다.

## 02 콘텐츠·행동 인벤토리

- 상자 자체는 작은 A1 소개만; 보상 아이템 3개는 보상 미리보기 **Media+Identity+획득조건**.
- 기존 큰 광고 Hero의 카피와 같은 목적지 링크 중복 삭제.

**G2:** 데이터 중복은 같은 수치가 서로 다른 맥락에서 쓰일 때만 허용하며 실제 화면에서 횟수 검사한다.

## 03 객체·정보 구조

- O-ITEM 맥락=보상 미리보기: Media 필수, Identity 필수, State=예정조건 필수, Price/Owned/Equipped/Buy Action 금지.
- O-PROGRESS는 현재/목표 단일값·10px Track·기한.

**G3:** O-ITEM/O-PROGRESS/O-PERSON-ACTIVITY 슬롯과 대표 클릭 대상 및 독립 행동을 검증한다.

## 04 선택·배제 근거

- 채택 C-IMAGE contain+Flat Item List, O-ITEM 슬롯. 배제 C-RARITY의 판매 가격/장착 상태, A2/A3 과잉 아트, 상품 구매 카드.

**G4:** 모든 핵심 표현에 대해 채택과 배제 후보를 함께 기록한다.

## 05 시각 위계

- 이미지·이름·조건이 동등한 리스트 한 행으로 읽히고 어떤 아이템도 비클릭인데 CTA처럼 보이지 않는다.

**G5:** 390×844 첫 뷰포트 실제 Chromium 위치 및 보조 대비로 판정하며 단순 스타일 선언은 통과 근거가 아니다.

## 06 구현·회귀

- 기존 상자/블루캡/헤드셋/비니 이미지 자산을 재사용하고 조건이 미확정임을 설명. 지급/장착 기능 추가 금지.

**G6:** 공통 토큰, 바텀바, 모든 기존 버튼·탭·응원·초대·마스코트 조합을 실제 실행한다.

## 07 검증·반례·복귀

- **현재 상태: 구현 전 설계 기록**. G1~G6은 설계 후보이며 구현 성공이라고 단정하지 않는다. 렌더/계산스타일/인터랙션 결과는 P3 Actions 실행 후 기록.
- G7 판정 축: 실행 / 규격 / 객체·조합 / 목적 / 행동·회귀.
- 실패 발생 시 실패한 Gate로 복귀한다. 실기기 Android·TalkBack·실제 A2 아트는 범위 밖이며 미검증.
