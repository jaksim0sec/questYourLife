# 갓생패치 (questYourLife)

현실적인 목표를 퀘스트로 나누고, 앱 밖에서도 확인·완료할 수 있는 Android 우선 할 일 앱.

## 현재 개발 범위

**동작하는 기능**
- 크림·레드 브랜드 홈과 기존 도장 마스코트, 홈 / 퀘스트 / 기록 / 설정
- 매일 3개의 오프라인 일일 퀘스트 제안. *Gemini가 생성한 퀘스트가 아님*
- 사용자 **수락** 이후 퀘스트 진행 알림 발행, 앱 화면 또는 알림의 **완료** 버튼으로만 완료
- 완료 시 기기 내 캐시(C) 누적 및 완료 기록 반영. 같은 퀘스트 중복 보상 방지
- 알림에서 30분 미루기, 사용자 설정 시각(기본 07:00), 알림 on/off
- Room v1 -> v2 마이그레이션 (기존 `quests` 테이블 보존)
- 전원 재시작 및 시간/시간대 변경 시 다음 제안 알림 재예약
- GitHub Actions 자동 Debug APK 빌드

**아직 구현 안 됨**
- Gemini 목표 분해, 메인/챕터 구조, Supabase 로그인/동기화·랭킹
- 홈 위젯, 집중 타이머, 활동 조건(위치·걸음 수), 알림 커스텀 디자인
- 친구/지역 커뮤니티, 실제 캐시 교환 및 실시간 시즌 랭킹

## 알림 동작

1. 앱 설치 후 실행. Android 13 이상에서는 **설정 → 알림 권한 허용**.
2. 기본 오전 7시 이후 시스템이 알림을 전달하면 **오늘의 일일 퀘스트 제안**이 표시됨. **정시 보장은 안 됨**.
3. 앱에서 제안을 **수락**하면 진행 알림이 표시됨.
4. 알림에서 **완료**하면 Room에 기록되고 캐시가 한 번 지급됨.
5. **30분 후**는 알림을 숨겼다가 다시 보여주는 동작이며 완료가 아님.
6. 시스템에서 알림을 강제로 끄거나 앱을 강제 중지한 경우 전달 보장 안 됨.

**설치 직후 7시까지 기다릴 필요 없음.** 홈에 오늘의 로컬 제안을 생성해 바로 수락/완료 테스트 가능.

Android에서는 일반 예약 알림을 지연할 수 있어 `AlarmManager.setAndAllowWhileIdle` 사용. 정확 알람 권한을 요구하지 않음. 진행 알림에 `setOngoing`을 사용해도 Android 14+에서 사용자가 닫을 수 있음.

## 모바일 빌드

1. [GitHub Actions](https://github.com/jaksim0sec/questYourLife/actions/workflows/android-apk.yml) 열기
2. 가장 최근 성공한 Android Debug APK → Artifacts → `hyunsaengpatch-debug-apk`
3. ZIP 다운로드 → `app-debug.apk` 설치. Termux 불필요
4. 같은 앱에 덮어 설치하려면 **서명 키 일치**가 필요함. Actions 캐시 키는 장기 보존 보장 없음

개발: Kotlin, Jetpack Compose, Room, AlarmManager, Notification API, Gradle 8.13, GitHub Actions.

## UI 갱신
- 시안 기준 홈/퀘스트/메인 상세/완료/일일/기록/꾸미기/타이머 구현.
- 메인 목표는 최초 실행에서 **예시**로 생성됨. 새 목표는 수동 7단계 가이드로 생성(아직 Gemini 아님).
- Room 3으로 갱신하고 v1→v2→v3 데이터를 보존하는 마이그레이션 제공.
- 캐시는 실제 일일·메인 완료 보상에서 구매 비용을 뺀 값.
- 정식 자동 업데이트는 미구현. `PREVIEW_DEBUG_KEYSTORE_B64`는 **기존 앱과 동일 서명키**를 설정해야 덮어쓰기 가능.
- 단일 성공 빌드만으로 외형 일치/실기기 안정성까지 검증됐다고 주장하지 말 것.

### 빌드 채널과 서명

- 설치용 APK 아티팩트는 **main 브랜치 빌드에서만** 제공. PR의 임시 서명 APK 설치는 업데이트 충돌을 일으키므로 비활성화함.
- 고정 서명용 GitHub Secrets 이름: `PREVIEW_DEBUG_KEYSTORE_B64`. 값은 **현재 설치된 APK와 같은 debug.keystore를 base64 인코딩한 문자열**이어야 함.
- 이 Secret이 설정되지 않은 상태에서는 GitHub Actions Cache 키에 의존하며, 캐시가 사라지면 다시 충돌할 수 있음.
- 어떤 방식도 기존에 다른 키로 서명된 앱을 덮어쓸 수 없음. 이전 설치본 데이터 보존이 중요하면 앱을 지우기 전에 백업 경로부터 확보.

## 2026-11-01: 설치 충돌 방지

- 로그상 이전 `actions/cache` 저장이 `debug.keystore` 파일 부재 때문에 실패하여 실행마다 디버그 서명 인증서가 달라질 수 있었음.
- 새 디버그 빌드는 `com.questyourlife.app.preview`로 설치됨. 기존 `com.questyourlife.app`과 **동시에 설치 가능**하며 이전 앱/데이터를 삭제하지 않음.
- 기존 앱의 데이터가 새 프리뷰로 자동 복사되는 것은 아님. 2개 앱은 독립 저장소임.
- 이후 **동일 preview 앱 업데이트**는 기존 서명키를 재사용해야 함. 새 워크플로가 최초 빌드 전 키를 생성하고 캐시하지만 영속성이 없음.
- 진정한 고정키 설정: GitHub Settings → Secrets and variables → Actions → New repository secret에 기존 디버그 키를 Base64로 인코딩해 `PREVIEW_DEBUG_KEYSTORE_B64`에 보관. 인증서가 이미 설치된 preview APK와 동일한 키여야 함.

## 2026-11-02: 갓생패치 · 클랜 화면 개편

- 앱 표시 이름을 갓생패치로 변경. 기존 패키지·서명·로컬 데이터 식별자는 유지.
- 클랜 시연에 맞춰 공동 상자 영역, 얼굴 기록, 멤버 기여도, 주간 순위를 재구성. 나침반 SVG 유지, 상자 그림 자리와 아바타 착장은 사용자 요청대로 비워 둠.
- 클랜 정보는 임시 게이트웨이의 예시 데이터이며 개인 캐시 원장에 반영되지 않음. 기간 선택·예시 코드 복사/공유·주변 순위 안내 구현.
- [구현 범위와 검증 기록](docs/development/clan-reference-checklist.md). 실제 기기 확인은 사용자가 진행.
