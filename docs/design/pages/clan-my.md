# 내 클랜 · P3 Page Record

> [SEED PROCESS](../seed/PROCESS.md) · [4유형](../seed/pages/page-types.md) · [21개 계약](../seed/INDEX.md). 웹 Preview는 픽션 데이터이며 실제 지급·가입/구매 저장을 구현하지 않는다.

## 01 Page Intent

| 필드 | 결정 |
|---|---|
| 유형 | 글로벌이너 (Standard+Back, 클랜 탭 유지) |
| 과업(동사) | 클랜 구성원과 각자 공개한 참여 정보를 탐색한다 |
| 목적 | 내 클랜 멤버의 구성과 활동 범주를 명확히 나눠 접근한다 |
| 주연 1개 | 멤버 Flat List |
| 대표 행동 1개 | 멤버 탭을 선택해 멤버 정보를 읽는다 |
| 핵심 데이터 | 깃발·클랜명·멤버 Identity/공개 메타, 현재 선택 Tab Panel |
| 보조 데이터 | 기록·소식 Tab, 초대 진입 |
| 다른 화면 책임 | 주간 전체 기록→#clan-record, 보상 상세→#clan-reward, 초대→#clan-invite |
| 제외 목록과 이유 | 보유 아이템 Grid·반복 Hero·행별 그림자·실제 비공개 기록 노출 금지 |

**G1:** 주연 1개/대표 행동 1개/제외 목록 확보. 구현 후 첫 뷰포트 실측으로 재판정한다.

## 02 콘텐츠·행동 인벤토리

- 현재 3탭(멤버/기록/소식)은 실제 Panel 데이터가 변한다는 점에서 유지. 멤버 8명과 시연에서 보이는 네 명을 혼동하지 않게 설명.
- 클릭 불필요 행에는 chevron/pressed 없음.

**G2:** 데이터 중복은 같은 수치가 서로 다른 맥락에서 쓰일 때만 허용하며 실제 화면에서 횟수 검사한다.

## 03 객체·정보 구조

- O-PERSON-ACTIVITY Identity/Meta. Members는 정적 목록, Activity Panel만 Cheer 버튼을 갖는다.
- 동일 멤버 정보는 각 Panel의 목적이 다르므로 맥락 설명을 붙인다.

**G3:** O-ITEM/O-PROGRESS/O-PERSON-ACTIVITY 슬롯과 대표 클릭 대상 및 독립 행동을 검증한다.

## 04 선택·배제 근거

- 채택 C-TABS Panel+Flat List, O-PERSON-ACTIVITY. 배제 Segment(별도 콘텐츠 범주), 카드 Tile, 잘못된 +N.

**G4:** 모든 핵심 표현에 대해 채택과 배제 후보를 함께 기록한다.

## 05 시각 위계

- Tab 선택/ARIA/Panel이 함께 바뀌며 첫 멤버 행이 시선 주연이다.

**G5:** 390×844 첫 뷰포트 실제 Chromium 위치 및 보조 대비로 판정하며 단순 스타일 선언은 통과 근거가 아니다.

## 06 구현·회귀

- 기존 탭 키보드 화살표/초대/깃발·장비 조립 보존, 상태와 Page scroll 유지. 신규 멤버 데이터 생성 금지.

**G6:** 공통 토큰, 바텀바, 모든 기존 버튼·탭·응원·초대·마스코트 조합을 실제 실행한다.

## 07 검증·반례·복귀

- **현재 상태: 구현 전 설계 기록**. G1~G6은 설계 후보이며 구현 성공이라고 단정하지 않는다. 렌더/계산스타일/인터랙션 결과는 P3 Actions 실행 후 기록.
- G7 판정 축: 실행 / 규격 / 객체·조합 / 목적 / 행동·회귀.
- 실패 발생 시 실패한 Gate로 복귀한다. 실기기 Android·TalkBack·실제 A2 아트는 범위 밖이며 미검증.
