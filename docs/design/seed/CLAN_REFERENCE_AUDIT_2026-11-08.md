## 3. 원인 분해

- **근본 구조 원인 (code):** `identity()`·`rewardSection()`·`feedSection()`가 각각 비슷한 굵기와 라벨을 갖는 계층을 강제한다. `clan-layout`이 모든 섹션을 같은 테두리/구분으로 나눈다.
- **정본의 실질 공백 (seed):** `P-HIERARCHY`에 방향은 있었으나 '데이터 타입별로 어떤 컴포넌트가 주연인가'의 사례가 부족하다. `A-ART` 역시 A2 실제 점유·반복 문구 검수 규칙이 약했다.
- **구현자의 오용:** 기존 C-TEXT, C-SURFACE, C-STATUS를 한 화면에서 최대한 많이 노출하면 잘한 디자인이라는 접근. 이 문제는 SEED 규격 자체의 결함이 아니라 준수 실패다.
- **하지 않을 일:** 당근 화면 카피/브랜드/상표/상품 이미지의 복제, 클랜의 새 서버 기능/DB 정책 추가, RootNav/StandardNav 재발명, 설명할 필요 없는 새 UI 컴포넌트 등록.

## 4. 검증 체크리스트

- [ ] 320/390/430px × Dark/Light 실브라우저 캡처
- [ ] 100/200% 글자 확대에서 내용 가림·가로 넘침·터치 크기
- [ ] Root joined/guest, My members/record/activity, Reward, Discover 이동
- [ ] 보상 이미지 실제 decode, contain 크롭, A2 상대 시각 강조
- [ ] 하단 네비 active/current 및 기존 탐색/Sheet/Menu
- [ ] 투명 마스코트 얼굴/아이템/깃발 색상 프리뷰
- [ ] 시연에서 미지원 서버 저장/보상 지급을 되는 것처럼 주장하지 않음

**정적 코드 검사와 실브라우저 픽셀 검수는 별개**다. 후자를 직접 실행하지 못하면 완료로 기재하지 않는다.


## 5. QA 수행 기록 · 2026-11-08

- 기존 JS/CSS에 대한 RED 5개 확인: 제목 중복, 삼분할 액션, A2 좁은 비중, 헤더 면색 차이, 초대 위치.
- 수정 JS 13개 경로 렌더링과 구조 GREEN 14개 조건 확인. 컴포넌트 추가·백엔드 호출 없음.
- **내부 독립 레이아웃 fixture**(최종 사이트 코드가 아님)로 Playwright Chromium 320 / 390 / 430 CSSpx에서 뷰포트 밖 문서 넘침이 0인 것을 관찰. Fixture의 390px 보상 Hero 상단은 약 236px. 이 확인은 실제 GitHub Pages의 DOM, 모바일 서체, 이미지/마스코트 합성, 클릭 동작이 맞다는 보증이 아님.
- 보조 액션 Invite/Chat/Reward preview의 CSS 최소 터치 크기를 `3rem`으로 보정. 시뮬레이터 320px 기준 48px, 390px 기준 root에 따라 증가.
- 실제 공개된 Pages 캡처/Light·Dark 전체/200% 확대/실기기와 서버 동작 검수는 미실시, 승인 게이트 통과 주장 불가.
