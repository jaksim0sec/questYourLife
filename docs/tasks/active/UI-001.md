# UI-001 · 갓생알리미 기술 계승

- 상태: IN_PROGRESS. INFRA-001의 원격 문서·등록은 반영됨; Node 검증은 독립 미완료로 남기며 이 작업의 디자인 조사/격리 CSS 변경을 차단하지 않는다. 요청된 방향은 버튼·타이포 활용, 디자인 완성도와 일관성, 온보딩, 이펙트·알림창·애니메이션 등 갓생알리미에서 익힌 구현/표현 기술의 계승.
- 비목표: 갓생알리미의 화면·브랜드를 그대로 복제하거나 갓생패치의 소셜 퀘스트·도장 마스코트·보상 정체성을 덮어쓰기. 권한·개인정보·동작 감소 등 접근성 경계 보존.
- [갓생알리미 실제 HTML/CSS 기준 4d9a706](https://github.com/jaksim0sec/godseng-alarm/blob/4d9a706aeed572f5aed3e2659c069def3f737e33/app/src/main/assets/index.html)의 표현을 조사했다. 기존 [SEED](../../../seed/INDEX.md) 승인 범위와 [OPEN](../../OPEN.md)의 미결을 비교한다.

## T1 기술 비교 및 계승 기준

버튼 상태·타이포 위계·여백/표면·디자인 일관성·이펙트·알림창/시트·모션·온보딩을 실제 소스와 시연으로 대조한다. 그대로 재사용/갓생패치에 맞게 변경/채택 제외를 구분하고 기존 확정 사항과 충돌을 기록한다. 변경된 정본과 실제 검증 기준을 준비한다.

## T2 공통 UI 표현 및 피드백

T1에서 합의된 범위만 기존 SEED/공통 CSS·런타임에 적용한다. 버튼 및 타이포, 여러 화면의 동일 상태, 알림/모달·이펙트·애니메이션을 비교한다. 실제 모바일 폭, 라이트/다크, 글자 확대, 키보드·동작 감소, 상태/회귀 확인.

- 1차: 기존 공통 버튼 face, 아이콘, Filter Chip의 press/transition 및 native Switch 스타일을 기존 CSS에 추가. 실제 기능·승인 치수/브랜드 값 변경 없음. Switch는 소비 페이지 미연결이며 신규 설정을 만들지 않음. 테스트 2개 추가, 실제 Node/브라우저 실행 NOT RUN.
- 2차: 실제 웹 preview에서 `?design=refined`로 동일 데이터·라우트의 시각 비교안을 실행할 수 있게 연결했다. Root만 큰 제목/높이, Section·Hero·Number의 위계, 일반 Surface 면/곡률, 알림·메시지 시트의 내용 높이와 제목·여백, Dialog·Snackbar 진입 효과를 후보로 구현했다. 새 Page Type/Variant/기능·저장 변경 없음. 기존 D-015/토큰/기본안은 유지. Switch 소비 연결 및 퇴장 모션은 3차에서 처리.
- 3차: refined 메뉴에서 기존 다크 모드를 native Switch에 연결. 저장 키·기능 동일, 입력 포커스와 메뉴 유지. 기존 native dialog close를 지연하지 않고 지원 브라우저에서 display/overlay 퇴장 180ms를 적용, 미지원 환경은 즉시 닫기. Snackbar 퇴장/타이머 취소·동작 감소 대응. 새 기능/저장 구조 없음.
- 검증: 변경 전후 소스·정적 계약을 대조하고 테스트를 추가했다. 실제 Node/브라우저 및 실기기 NOT RUN. 다음: 320/360/390/430px·라이트/다크·200% 글자, 실제 알림/DM/퀘스트 동작과 reduced motion 비교, 비례 승인 및 필요한 수정. T2 종결 아님.

## T3 온보딩 경험

T1의 기술 비교와 T2의 공통 UI를 기반으로 진입·설명·권한 요청·거부·재시도·완료/재진입 상태를 시연한다. 실제 Android 권한과 웹 모의 흐름을 구분하며 강제 동의나 불필요한 요청을 피한다. NOT RUN.

최종 게이트: 사용자 시각 승인 범위와 실제 기능 검증 분리. Android 이관과 출시 자체는 별도 범위. T 분할은 작업 시작 전 검토 가능하며 시작한 ID는 고정.
