# 현생패치 제품 개편 설계안

작성: 2026-11-02 (Asia/Seoul). 상태: 사용자 검토 전 초안. 구현·화면 시안·출시 완료 문서가 아니다.

## 1. 의도와 합의

현생패치는 내 삶의 목표를 실행 가능한 퀘스트로 만들고, 성취를 쌓으며 삶을 조금씩 패치하는 Android 앱이다. 주요 감성 대상은 한국 초·중·고등학생이다. 학습뿐 아니라 운동·취미·생활 목표도 다룬다.

사용자가 직접 밝히거나 선택한 방향:

- AI와 자연스럽게 상담해 목표와 계획을 만든다. 사용자 수정과 수동 입력도 지원한다.
- AI는 마스코트와 이어지는 DM 같은 비서다. 새 프로젝트 생성 후에도 대화로 계획을 관리한다. 일회성 생성 화면으로 끝나지 않는다.
- 목표 → 챕터 → 메인 퀘스트 → 일일 퀘스트. 일본어 1년 목표의 예는 기초 문자 챕터 → 히라가나 외우기 → あ행 익히기다.
- 설정 시각에 일일 퀘스트를 제안하고 사용자가 수락한 뒤 진행한다. 하루 제안은 여러 개일 수 있다.
- 우리가 설계한 퀘스트 모델·가이드라인과 재사용 세트를 기반으로 AI가 개인화한다.
- 자기 확인 완료가 기본이다. 일부 퀘스트는 걸음 수·위치 등의 달성 조건을 가진다.
- 포기·미루기는 필요하며, 구체적인 정리 방식은 설계자에게 맡겼다.
- 개인 퀘스트를 중심에 두고, 게임의 클랜 같은 지속적인 팀 소속으로 함께 성장하고 경쟁한다.
- 캐시·꾸미기·상자와 완성도 높은 이펙트가 경험의 중요한 부분이다.
- 마지막 첨부의 빨간 도장 얼굴은 마스코트이자 앱 아이콘 원본이다. 국내 앱 하단 내비게이션 참고는 품질·감성의 참고이며 복제 지시가 아니다.
- 기존 시연본의 구성·배치를 유지할 필요 없이 전반적으로 개편한다.

이하 세부 규칙은 위 방향을 구체화한 **설계자 제안**이다. 수치·정책·화면을 사용자가 이미 확정했다고 해석하지 않는다.

## 2. 고려한 접근과 선택

1. 클랜 중심: 팀 활동·공동 미션·팀 순위가 앱 방문의 중심. 함께할 사람이 있을 때 강하지만 혼자 시작하는 경험이 약해진다.
2. 개인 퀘스트 중심 + 클랜: 개인 상담·계획·실행이 독립적으로 동작하고, 그 성취가 공동 보상과 경쟁에 연결된다.

사용자는 두 번째 방향에 동의했다. 이후 AI를 마스코트와 DM하는 지속적인 비서로 구체화했다. 기존 앱의 기능 배치를 보존하는 소규모 외형 수정은 요청에 맞지 않아 채택하지 않는다.

## 3. 마스코트 DM과 AI 계획

### 지속적인 대화

- 앱 안에서 언제든 돌아올 수 있는 대화 공간을 제공한다. 대화 기록과 진행 중인 목표 맥락을 이어간다.
- “일본어를 배우고 싶어”로 새 프로젝트를 만들고, “오늘은 10분밖에 없어”, “이 부분은 이미 알아”, “다음 단계로 가자”로 기존 계획을 조정한다.
- 상담, 퀘스트 조회, 계획 초안, 실제 적용 결과를 구분한다. 실행되지 않은 변경을 “바꿨어”라고 답하지 않는다.
- 새 프로젝트·여러 단계 재편은 대화 안의 계획 초안에서 수정·확정한다. 명확한 단건 명령인 “이거 내일로 미뤄줘”는 즉시 반영하고 결과와 되돌리기를 제공한다.
- 대명사나 대상이 모호하면 해당 퀘스트를 확인한다. 대화 답변 텍스트 자체가 DB 명령이 되지는 않는다.
- AI가 먼저 이야기할 때는 오늘 제안·진행 점검 등 사용자가 허용한 계기에서만 시작한다. DM을 열었다고 보상이나 계획이 바뀌지 않는다.

### 계획 생성과 재사용

1. 대화에서 목표, 현재 수준, 기한, 하루 가용 시간, 선호·제약을 파악한다. 아는 정보를 다시 긴 설문으로 묻지 않는다.
2. 검토된 세트를 주제·목표 수준·시작 수준·가이드 버전으로 조회한다.
3. 적합한 세트는 재사용하고 분량·시작 단계·속도를 조정한다. 없으면 동일 모델로 생성·검증한다.
4. 장기 경로는 큰 단계로, 가까운 실행 구간은 구체적으로 제안한다. 1년 전체를 고정된 수백 개 일일 퀘스트로 생성하지 않는다.
5. 사용자 확정 후 저장한다. 이후 상담·실제 진도에 따라 미완료 구간만 조정한다.

공유 캐시는 개인 대화와 분리된 퀘스트 템플릿이다. 생성 결과가 자동으로 검토된 공용 세트가 되지는 않는다. 템플릿의 버전과 출처를 보존하고, 진행 중 계획은 원본 버전에 연결해 캐시 갱신으로 바뀌지 않게 한다.

AI는 구조화된 도구 요청으로 조회·생성·수정을 제안한다. 서버/클라이언트는 부모 관계, 완료 조건, 예상 분량, 허용된 상태 전이를 검사한다. 보상 금액·랭킹 계산은 결정적인 정책으로 처리하며 AI가 임의 발행하지 않는다.

## 4. 퀘스트 모델과 하루 운영

| 단위 | 의미 | 예시 |
| --- | --- | --- |
| 목표/프로젝트 | 사용자가 이루려는 장기 변화 | 일본어로 일상 대화하기 |
| 챕터 | 큰 학습·실행 구간 | 기초 문자 익히기 |
| 메인 퀘스트 | 챕터 안의 의미 있는 성취 | 히라가나 외우기 |
| 일일 퀘스트 | 오늘 수행하고 확인할 행동 | あ행 5글자 읽고 써보기 |

- 일일 퀘스트는 부모 메인 퀘스트와 연결한다. 독립적인 생활 할 일은 부모 없이도 수동 생성할 수 있다.
- 완료 조건·예상 시간·보상을 수락 전에 알 수 있게 한다. 선행 조건은 필요한 경우에만 둔다.
- 메인 완료 조건은 생성 때 명시하고 일일 수행과 연결한다. 일일 퀘스트 개수와 메인 진도를 동일시하지 않는다. 복습 퀘스트는 같은 단계의 진도를 중복 올리지 않는다.
- 여러 목표를 진행해도 하루 가용 시간을 함께 사용한다. 미룬 퀘스트를 먼저 반영하고 새 제안을 줄인다. 매일 무조건 3개를 만들지 않는다.
- 예약 시각 전에 준비된 개인화 계획/세트로 오늘 제안을 확정한다. 알림 수신 때 AI 응답을 기다리지 않는다. 새 온라인 상담이 불가능하면 기존 계획을 이용한다.
- Android 일반 예약 알림은 정시 전달을 보장하지 않는다. 알림 권한이 없어도 앱에서 제안·수락·진행을 할 수 있다.

제안 상태 모델: 제안됨 → 수락됨 → 완료됨. 수락 전에는 시작된 것으로 보지 않는다. 미루기·그만하기는 별도 기록을 남긴다.

- 내일로 미루기: 같은 실행 항목의 예정일을 옮긴다. 복제하지 않고 수락 상태와 조건 진행도를 유지한다. 날짜 제한 조건의 재측정이 필요하면 이동 전에 설명한다.
- 이번 퀘스트 그만하기: 해당 실행을 종료한다. 부모 목표와 과거 성취는 유지하고 보상은 지급하지 않는다. 목록에서는 정리하고 기록에서 확인한다.
- 날짜가 지났다는 이유만으로 실패·포기를 확정하지 않는다. 지난 미완료 항목을 정리해서 이어갈 수 있게 한다.
- 반복 미루기는 자동 벌점 대신 분량 축소·대체 행동을 DM에서 제안한다.
- 단건 되돌리기와 완료 취소를 지원한다. 보상·클랜 기여도의 역거래를 같은 이벤트에 연결해 재완료로 중복 이득을 얻지 않게 한다. 이미 소비한 재화가 있으면 부족분을 다음 적립에서 정산하고 구매·기록을 삭제하지 않는다.

걸음·위치 조건형은 수락 후 명시된 조건을 만족해야 완료 선언이 가능하다. 권한 거부·측정 불가를 달성으로 처리하지 않으며, 사용자 동의로 자기 확인형 대체 퀘스트를 선택할 수 있다. 위치 조건은 사용자에게만 보이고 클랜에 좌표나 목표 상세를 공개하지 않는다.

## 5. 캐시·클랜·상자

### 개인 보상

- 보유 캐시와 주간 퀘스트 획득량을 별도로 계산한다. 꾸미기에 소비해도 주간 성취량은 내려가지 않는다.
- 출석·상자·이벤트 캐시는 퀘스트 수행으로 얻은 경쟁 점수와 분리한다. 돈을 쓰거나 상자를 열어 순위를 구매하지 않는다.
- 성취율은 개인 계획의 진도를 보여준다. 연속 접속과 실제 수행 연속일은 구분한다.
- 첫 보상 정책은 일일 실행에 캐시를 지급하고 메인·챕터 완료는 도장/기록/연출로 축하하는 방식으로 제안한다. 계층마다 같은 행동에 캐시를 거듭 지급하지 않는다.

### 클랜

- 지속적인 소속, 이름·아이콘, 초대/가입·탈퇴, 멤버, 개인 기여도, 주간 공동 목표·상자, 클랜 간 주간 순위가 기본 기능이다.
- 초기 제안은 1인 1클랜, 초대 기반 소규모 클랜, 방장·멤버 역할이다. 정원 등 운영 수치는 구현자가 조정 가능한 설정으로 둔다.
- 클랜 없이도 DM·개인 퀘스트·보상·꾸미기를 이용한다. 첫 목표 생성에 가입을 강제하지 않는다.
- 서로 다른 목표를 수행해도 주간 퀘스트 획득량이 클랜 기여도가 된다. 기본 순위는 확정된 주간 기여도 합계다. 초기에는 정원이 같은 클랜끼리 비교한다.
- 주간 경계는 Asia/Seoul 월요일 00:00으로 제안한다. 완료 이벤트 시각의 주차·소속을 고정해 탈퇴/재가입으로 기여도를 중복 이동시키지 않는다.
- 클랜에는 닉네임·꾸미기·기여도 등 공유 정보만 보여준다. 개인 대화·목표 상세·조건 측정값은 자동 공유하지 않는다.
- 온라인 확정 순위와 동기화 대기 기여도를 구분한다. 재접속 시 확정 결과를 받아 갱신하고 실시간 연결 중복 수신으로 보상을 재지급하지 않는다.

### 공동 상자

- 팀원의 수행 기여로 주간 상자를 완성한다. 캐시 기부를 필수로 하지 않는다.
- 상자 목표·보상·수령 조건을 미리 알린다. 초기안은 고정된 꾸미기 보상 중 선택하는 방식이다. 확률형·유료 상자 여부는 이 설계에서 채택하지 않는다.
- 상자 달성 순간의 소속과 최소 1회 유효 기여가 있는 멤버에게 주간 수령 권리를 고정한다. 이후 이동으로 권리를 복제하지 않는다.
- 수령은 서버에서 사용자/클랜/주차별 한 번만 확정한다. 보상을 저장한 후 개봉 연출을 실행하며 앱이 종료돼도 다시 결과를 확인할 수 있다.
- 완료 취소로 줄어든 기여도는 순위에 반영한다. 이미 확정한 주간 상자 권리는 회수하지 않는 단순 정책으로 시작한다.

상품권 교환은 수익 모델·전환 정책이 결정된 이후의 별도 범위다. 현재 캐시가 현금과 교환된다고 표시하지 않는다.

## 6. 브랜드·화면·손맛의 기준

첨부 마스코트의 둥근 얼굴, 양옆 귀, 눈, 열린 입, 빨간 인주 질감을 보존한다. DM 상대와 완료 축하, 꾸미기의 동일 캐릭터다. 이름·말투·성별 등은 임의의 공식 설정을 만들지 않는다. 친근하고 짧은 한국어를 쓰되 유아어·억지 유행어를 기본으로 삼지 않는다.

저장소에서 직접 확인한 기존 자산:

- `app/src/main/res/drawable-nodpi/launcher_stamp.webp`: 원본과 같은 얼굴·종이 배경의 축소본.
- `app/src/main/res/drawable-nodpi/mascot_sticker.webp`: 투명 배경의 매우 작은 얼굴 자산. 큰 DM/개봉 연출에 확대해 사용하면 품질이 부족하다. 원본 첨부를 기준으로 고해상도 원본·컷아웃 확보가 필요하다.

기존 크림·오프화이트와 스탬프 레드는 출발점이다. 기존 핑크 카드, 산·새싹 일러스트, 모서리·간격·탭 배치는 유지 의무가 없다. 종이 질감은 브랜드 자산과 성취 순간에 집중한다. 본문에는 선명한 한국어와 빠른 상태 파악이 우선이다.

필요한 주요 사용 목적은 오늘 수행, 목표 경로 탐색/수정, 마스코트 DM, 클랜, 내 성장·꾸미기다. 정확한 탭 수·명칭·배치는 다음 시안 비교에서 정한다. DM을 숨겨진 일회성 버튼으로 두지 않는다는 조건은 고정한다. 기존 4탭을 보존한다는 과거 내비게이션 초안의 범위 제한은 이번 전면 개편에 적용하지 않는다.

하단 내비게이션은 참고 앱처럼 같은 시각적 무게의 아이콘·짧은 라벨·즉각적인 선택 구분·안정된 기준선을 갖춘다. 참고 이미지의 검은 배경이나 다른 회사 고유 아이콘을 복제하지 않는다.

연출의 제안 기준:

- 탭/버튼 반응: 100~180ms 수준의 즉각적인 눌림·선택 피드백. 화면 전체가 과장되게 튀지 않는다.
- 일일 완료: 300~600ms 수준의 도장 반응·숫자 변화·짧은 진동. 다음 행동을 막지 않는다.
- 메인/챕터 완료: 목표의 실제 변화와 함께 더 큰 축하. 자동으로 매번 긴 전체 화면을 강제하지 않는다.
- 상자: 기대 → 열림 → 보상 확인의 1~2초 내외 연출. 건너뛰기·소리/진동 끄기·동작 줄이기를 지원한다.
- DM: 입력·응답·계획 적용 결과가 자연스럽게 연결된다. 장식용 타자 애니메이션 때문에 내용을 기다리게 하지 않는다.

정확한 타이밍과 에셋은 실제 Android 영상에서 조정한다. 연출 중 재탭·프로세스 종료·화면 회전에도 보상 처리는 한 번만 일어난다. 큰 글씨, TalkBack, 48dp 이상 터치 영역, 시스템 인셋을 검증한다.

## 7. 기존 구현과 기술적 경계

현재 코드를 읽어 확인한 상태: Kotlin/Compose, Room v3, 로컬 일일 세트 3개, 목표와 번호 기반 단계, 수락·완료 알림, 구매·장착·집중 기록. 일일 항목에는 부모 메인 ID가 없고, 목표 단계는 위치와 챕터 번호로 식별된다. 실제 Gemini 상담·계정·클랜·서버 순위는 없다.

유지할 기반: 현재 Android 툴체인, Room 로컬 저장, 알림 액션, 멱등 완료, 기존 앱·데이터 식별자. AI/온라인 구조는 기존 기획의 Gemini + Supabase Edge Functions/Auth/Postgres/RLS를 기술 출발점으로 삼는다. SDK·서비스 버전 선택은 구현자가 맡는다.

필요한 추가 모델: 안정된 ID의 목표/챕터/메인/일일 실행, 계획·템플릿 버전, 대화/메시지/실행 요청, 완료·보상 원장, 장착/소유권, 동기화 대기 이벤트, 클랜/기간별 소속/기여/상자 권리. 순서 변경으로 ID나 완료 이력을 바꾸지 않는다.

- 로컬 체크와 진도는 즉시 저장한다. 온라인 동기화는 이벤트 ID로 멱등 처리하며 서버 확정 재화와 대기분을 구분한다.
- AI 키는 앱에 넣지 않는다. 비공개 개인 대화와 공용 템플릿을 분리한다. 실제 연결이 없으면 상담·순위가 작동하는 척하지 않는다.
- 신규 DB 버전과 명시적 v3 이후 마이그레이션을 설계한다. 기존 v1/v2/v3의 퀘스트·완료·캐시·구매를 보존한다. 임시 7단계 가이드를 사용자 동의 없이 AI 계획으로 갈아끼우지 않는다.
- 클랜·상자·DM 서비스 연결에는 실제 프로젝트 설정이 필요하다. 이번 문서 작성 단계에서는 연결·인증·비밀값·게시를 변경하지 않는다.

## 8. 구현 묶음과 완료 기준

전체 방향은 한 프로젝트지만 검증 가능한 묶음으로 나눈다. 뒤 묶음을 첫 UI 구현에서 완료했다고 표시하지 않는다.

1. **시안과 개인 퀘스트 기반:** 홈/목표/DM/클랜/내 성장의 실제 사용 흐름과 디자인 방향 비교. 승인된 시안으로 UI를 재구축하고 모델 연결·미루기·그만하기·데이터 보존을 검증한다. 미연결 AI/클랜은 명확히 표시한다.
2. **지속적인 마스코트 DM:** 실제 상담, 세트 조회, 구조화 계획, 수정·확정·적용 결과, 저장된 대화 복원, 일일 제안과 재조정까지 연결한다.
3. **클랜·보상·연출:** 실제 가입·탈퇴, 이벤트 동기화, 공동 상자, 주간 순위, 꾸미기와 보상 이펙트를 연결한다.
4. **조건형 퀘스트:** 걸음 수·위치 측정과 권한·재시작·측정 오류·대체 선택을 검증한다. 위젯 등 기존 로드맵은 후속 범위로 남기며 미구현을 숨기지 않는다.

의미 있는 검증 항목:

- DM으로 프로젝트 생성 → 초안 수정 → 확정 → 앱 재실행 → 이어서 대화/조회. 일일 퀘스트가 올바른 메인에 연결돼야 한다.
- AI 오류/취소/재전송에서 이중 생성·조용한 데이터 교체가 없어야 한다. 네트워크가 없을 때 기존 개인 퀘스트는 수행 가능해야 한다.
- 수락 전 완료 제한, 중복 알림 액션, 미루기 다음 날의 총분량, 종료·되돌리기·재완료와 보상 원장을 확인한다.
- 두 계정 이상의 클랜 가입/주간 기여/탈퇴·재가입/오프라인 재전송/상자 중복 수령을 검증한다. 개인 비공개 정보 접근은 차단돼야 한다.
- 앱 종료 후 미수령/수령 상자와 보상은 보존돼야 한다. 연출이 보상 지급 여부를 결정하면 안 된다.
- 기존 데이터 마이그레이션, Debug 빌드, 실기기 알림·복원·권한·백그라운드 동작을 확인한다.
- 승인 시안과 동일 크기의 실제 화면을 나란히 비교하고 탭 이동·DM·완료·개봉 영상으로 손맛을 확인한다. 빌드 성공만으로 디자인 완료라 하지 않는다.

## 9. 사용자 검토와 구현자에게 맡기는 부분

문서 전체는 아직 승인 전이다. 특히 미완료 정리·보상 분리·클랜 운영·고정 선택형 상자·단계별 구현은 설계자가 채운 제안이다.

문서 검토에서 확인한 미결 사항(이번 기록·업로드를 막지 않으며 구현 전에 정한다):

- 계정 도입 시점, 비로그인 로컬 데이터의 계정 귀속, 기기 변경 시 복구 정책.
- 완료 취소 후 상자 권리를 유지할 때 한 사람이 클랜을 옮겨 같은 주 여러 클랜의 상자를 받을 수 있는지. 현재 제안만으로는 이를 금지하는 정책까지 확정되지 않았다.
- 첫 사용자 배포에서 실제 온라인 DM·클랜까지 함께 제공할지, 문서의 구현 묶음에 따라 나누어 배포할지.

다음 시안에서 확인할 사항: DM의 상시 접근 방식, 홈에서 오늘 수행과 마스코트의 비중, 실제 내비게이션, 캐릭터·상자의 아트 방향. 현재 글만으로 화면 외형을 승인한 것으로 보지 않는다.

구현자가 정할 부분: 클래스·파일 분할, 세부 DB 타입·API 이름·재시도 방식, 튜닝 가능한 보상량·정원·주간 목표치, 정확한 모션 곡선. 운영 정책과 변경 가능한 숫자는 코드에 흩뿌리지 않는다.

이 문서는 과거 기획을 삭제하지 않는다. 최신 사용자 요구와 충돌하는 기존의 ‘기존 4탭 유지’, ‘상자 등 게임 장치 일괄 금지’, ‘AI를 최초 생성 화면으로 제한’ 해석에 우선하는 새 개편안이며, 사용자 승인 후 구현 기준에 반영한다.
