# 퀘스트 · 현실을 플레이한다는 것

## 1. AI의 역할 [원칙]

사용자가 제공하거나 허용한 **상황·목표·생활 맥락**을 이해하고, 막연한 계획을 현실에서 수행 가능한 퀘스트로 바꾸는 것이 아이디어의 출발점. 위치·기기 데이터 접근은 필수가 아니며 별도 동의와 제품 필요성 검토 대상.

> “ai 를 통해서 내 상황이나 목표 같은걸 말하면 퀘스트로 만드는게 가능하지 않을까?”

퀘스트는 허구의 몬스터 처치가 아니라 내 현실에서 이루려는 일을 가리킴. 무엇을 얼마만큼 할 수 있는지는 개인 상황에 맞게 달라질 수 있음.

## 2. 퀘스트의 역설 [원칙]

> “퀘스트 자체는 재미있는 소재가 아니야.”

> “즉 퀘스트는 수단임. 단, 동시에 이 앱의 본질임.”

퀘스트 자체를 피드나 게임 보상만큼 자극적으로 포장하는 것보다, **내 행동에 의미를 붙이고 결과를 연결**하는 것이 역할임. 동시에 퀘스트를 제거하거나 의미 없는 출석 노동으로 대체하면 앱의 본질을 잃음.

- **입력**: 실제 목표·상황을 설명.
- **변환**: AI가 수행 가능한 도전과 흐름을 제안.
- **실행**: 사용자가 실제 생활에서 도전.
- **기록**: 사용자 스스로 수행과 완료를 확인.
- **연결**: 현실 행동이 나의 진행 기록과 재화·꾸미기·클랜 활동에 이어짐.

이 순서는 **제품적 의미를 정리한 개념 흐름**이지 확정된 단계형 화면·API 계약이 아님.

## 3. 한계와 신뢰

> “우리가 퀘스트 성취 조건을 완벽히 체크하고, 현실에서 보상을 주는 것은 불가능하므로”

앱은 외부에서 실제 행동을 모두 검증할 수 없음. 친구·클랜의 동료 의식과 경쟁이 자율적 수행을 도울 수 있지만 **친구를 강제 감독자나 사실 검증 기관으로 만드는 것은 미합의**임.

현재 저장소의 제품·기술 원칙에서는 **사용자가 완료를 직접 확인**하고, AI나 타이머가 자동 완료를 선언하지 않음. 새 제품 철학도 이를 변경한다고 말한 바 없음. 인증 방식·보상 악용 대응은 별도 검토 대상.

## 4. 기존 계층과의 관계 [미결]

현행 [IDEA.md](https://github.com/jaksim0sec/questYourLife/blob/main/IDEA.md)는 목표 → 챕터 → 퀘스트 구조를, 데이터 인프라는 더 복합적인 참여/반복 구조를 다룸. 이번 논의가 **새 계층 수나 저장 모델**을 다시 확정한 것은 아님. 사용자 제작 퀘스트북과 개인 실천 기록의 연결은 [QUESTBOOKS.md](./QUESTBOOKS.md), [OPEN.md](../OPEN.md)에서 설계해야 함.

## 5. 퀘스트 우선순위와 공통 구조 [최신 제품 방향 · 2026-11-12]

| 경험 | 역할 | AI가 하는 일 | 단계 |
|---|---|---|---|
| **습관 만들기** | 반복 행동을 내 일상에 정착 | 시작 난이도·빈도 제안, 오늘의 수행 내용 변주, 어려워진 날 대안 제안 | 핵심 |
| **루틴** | 여러 행동을 시간·상황에 맞게 연결 | 순서·분량 제안, 일정이 틀어졌을 때 현실적인 조정안 제공 | 핵심 |
| **목표 달성** | 달성할 결과를 향해 단계적 진행 | 목표→챕터→메인→일일 분해·진행별 수정 제안 | 베타 |
| **클랜 보너스** | 친구들과 가볍게 즐기는 깜짝 도전 | 사진·즉흥·협동형 보너스 미션 기획 | 부가 |
| **서버 보너스** | 전체 이용자의 제출·반응에 따른 추가 보상 | 이벤트 소재·참여 설명·제출 보조 | 부가 |

이 구분은 다섯 개의 DB 시스템·탭·퀘스트북 유형을 신설한다는 뜻이 아니다. 공통 수행/완료/기록 규칙 위에서 각 목적에 맞는 진행 정책을 구분한다. 기존 목표→챕터→메인→일일 계층의 실제 코드 적용은 별도 검토한다.

## 6. AI는 콘텐츠 제공자이자 적응형 진행 파트너 [최신 원칙]

- **발견:** 사용자가 직접 새 목표를 입력하지 않아도, 기존에 수락한 목표·습관·루틴과 허용된 상황을 바탕으로 '오늘 해볼 퀘스트'를 기획·제안할 수 있어야 한다.
- **수행 가능성:** 흥미로운 제목뿐 아니라 적절한 분량, 현실적 맥락, 실제 행동, 완료 기준이 있어야 한다. 유행 밈을 무작위로 접목하거나 체크리스트에 경험치만 붙이는 방식은 피한다.
- **진행·변주:** 이전 수행 기록을 반영하여 단조로운 반복을 줄이고, 어려움·시간 부족에 맞춰 대안을 제안한다. 같은 날 새로운 미션을 무한히 강요하지 않는다.
- **사용자 결정:** AI는 초안·변경안을 제안하고 사용자가 수락·수정·미루기·그만하기·완료/취소할 수 있다. AI·타이머·센서가 자동으로 실제 수행을 확정하지 않는다.
- **관계:** 친구가 공개에 동의한 퀘스트 활동은 함께할 계기로 사용할 수 있다. 클랜 소속·위치 추적·외부 서비스 연동은 전제 조건이 아니다.
- **데이터:** 트렌드 지표나 기기·서비스 연결은 그 데이터가 해당 퀘스트의 품질이나 실행을 실질적으로 높일 때에만 검토한다. 수집 범위·동의·노출·보존·API 운영은 별도 미결 사항이다.

## 7. 여전히 정해야 할 것 [미결]
