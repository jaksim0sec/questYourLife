# 콘텐츠 조합과 주목도

## 재사용 문법
페이지 과업과 주목 정보를 먼저 결정하고 목적에 필요한 콘텐츠와 관련 행동의 관계를 드러낸다. Section Header 선행은 가능한 구성 중 하나이며 모든 섹션의 의무가 아니다. 섹션마다 Card·Banner·배지·그림자를 덧붙여 경계를 증폭하지 않는다. 페이지 구성 순서·홈 콘텐츠 개수는 별도 화면 설계다.

| 조합 | 기본 재료 | 위계 기준 |
|---|---|---|
| 프로필 요약 | Avatar + 이름 + 짧은 상태 + 관련 Action | AvatarProfile과 type.item/section, 아트가 정보를 밀어내지 않음 |
| 비교 가능한 기록 | List Header + 반복 List Item + Numeric suffix | 동일 슬롯과 숫자 기준선, 순위마다 임의 높이 변경 금지 |
| 콘텐츠 발견 | Media Card + Title + Metadata | 썸네일로 맥락, 제목으로 목적, 보조는 절제 |
| 보상 진열 | Image Frame + 이름 + 실제 상태/값 | 균일 프레임·물체 점유율·상태 위치 |
| 진행 요약 | Title + 실제 값 + Progress + 관련 Low Action | 진행과 실행을 구분, 큰 숫자는 한 대표값 |
| 소셜 진입 | 공통 List Item + 현재 맥락 | 채팅 진입만 과한 배너/아이콘으로 따로 꾸미지 않음 |
| 강조 배너 | A-ART + 짧은 제목 + 선택적 행동 | 한 주목 그룹, 인접 CTA와 경쟁 검토 |

## S05 · 프로필 정보 역할: Big / Middle / Small (구성 패턴 제안)

**Big·Middle·Small은 아바타 픽셀 크기 3단계가 아니다.** 사용자가 이 대상의 정보를 **주로 읽는지, 다른 정보와 함께 식별하는지, 작은 자리에서 알아보는지**에 따른 **프로필 정보의 밀도·관계·행동 책임**이다. 같은 Big이라도 이미지 크기·가로/세로 배치·Surface가 달라질 수 있고, 다른 역할이 동일한 C-AVATAR scale을 쓸 수도 있다. 새로운 Profile 컴포넌트/Composite/Page Type·고정 카드 3종을 만들지 않는다.

| 정보 역할 | 대상·정보의 우선순위 | 기존 SEED에서 조합할 요소 | 맥락 예시 |
|---|---|---|---|
| **Big** | 화면 또는 큰 구역에서 **대상 자체가 주연**. 이름을 분명히 읽고 필요하면 상세를 확인 | 대표 아바타 **또는** 클랜 깃발 + **이름** + 선택적 상세/상태/메타 + 필요할 때만 관련 Action. 정보와 하단 Action 사이 **유연한 여백** 허용 | 마이페이지 본인 소개, 클랜 상세·정체성 |
| **Middle** | 목록·패널·헤더에서 **빠른 신원 파악과 맥락 확인**. 행동은 실제 진입 필요 시만 | 아바타/깃발 + **이름** + 선택적 보조 문구·상태 + 선택적 SVG 진입 표시/Action. 이름과 보조/후행 요소의 기준선 유지 | 랭킹, 클랜 멤버, DM 목록, Global의 인물 정보, DM·Global에서 이어지는 NonGlobal 채팅방 **Head 내비게이션의 상대 정보** |
| **Small** | 작성자·멤버·인라인 표시처럼 **짧은 위치의 최소 식별** | 작은 표시 영역의 아바타 + **이름**, 필요할 때만 역할/짧은 구분값. 긴 소개·추가 액션은 기본값 아님 | 피드 작성자, 인라인 멤버, 짧은 사용자 표시 |

```text
Big     [대표 아바타/깃발]   이름
                          상세·보조 정보?         (? 선택)
                          ··· 유연한 여백 ···
                          관련 Action?            (? 선택)

Middle  (아바타/깃발) 이름                  [SVG 진입?]
                     보조 정보?

Small   (아바타) 이름 · 역할?
```

- **Big의 유연한 간격:** 정보가 늘어나도 아래 Action이 텍스트 위에 겹치거나 마지막 줄을 자르지 않도록 내용의 자연 높이를 우선한다. 세로 여유 공간이 있을 때 `margin-bottom: auto` 등은 **가능한 구현 수단**일 뿐 필수 CSS 규칙·고정 높이 지시가 아니다. 버튼 없는 Big도 정상이다.
- **Middle의 두 사용 영역:** 반복 리스트라면 [C-LIST](../components/list-item.md)의 Prefix/Content/Suffix와 행 전체 링크 대 독립 조작 경계를 따른다. **Global 화면 또는 DM에서 진입한 NonGlobal 채팅방의 헤더**에서도 동일한 *정보 표현 원칙*을 재사용할 수 있으나, 헤더의 Back/Close·중앙 Title·우측 슬롯·하단 Nav 가시성은 [S-PAGE](../shells/page-shells.md) 및 NAV-TOP 정본의 책임이다. 실제 헤더 슬롯에 연결·검증하는 것은 **U06(S07)**이다. 지금 새 헤더 변형을 승인하지 않는다.
- **Small의 축약:** 둥근 Capsule·바깥 테두리·Divider가 반드시 필요한 것은 아니다. 짧은 사용 사례라도 **이름이 소실되면 신원 역할을 수행하지 못한 것**이므로 선택적 보조 정보부터 줄이고 이름은 줄바꿈/높이 증가 또는 실제 상세 확인 경로로 보호한다.
- **공통 슬롯과 동작:** Identity에 읽을 수 있는 이름을 남긴다. 이미지의 착장/표시/프레임·대체 텍스트는 [C-AVATAR](../components/avatar.md), 이름/메타의 의미 위계는 C-TEXT, 반복 행의 정렬/상호작용은 C-LIST, 간격·Surface·실제 Action은 해당 기존 정본을 재사용한다. 선택 정보·버튼·SVG 화살표는 **모두 필요할 때만**. 순수 상태/장식 표시를 클릭 버튼처럼 꾸미거나 링크 안에 독립 버튼을 중첩하지 않는다.
- **좁은 폭·긴 문자열:** 320/360/390/430 논리 폭과 200% 글자 확대에서 이미지가 이름·역할을 밀어내면 세로 재배치·가변 높이를 사용한다. 긴 한글 이름, 보조 문구 유무, 오른쪽 SVG 유무 및 마스코트 원본 착장 조합에서도 신원/메타/행동의 구별을 지킨다. 축소한 글씨·임의 고정 높이·원형 잘라내기로 대응하지 않는다.

**현재 시연에서 확인 가능한 구조 (최종 시각 승인 아님):** `web/preview/clan.js`의 `clan-my-detail`은 클랜 깃발과 이름·설명이 있는 Big 후보, `clan-member-detail`은 아바타·이름·선택적 한 줄 메타를 조합한 Middle 후보, `clan-social-person`은 아바타와 이름만 남긴 최소 정보 역할의 사례다. 마지막은 이미지 표시에 `hero` 크기를 사용해도 **정보 역할이 곧 아바타 크기라는 뜻은 아님**을 보여준다. `web/seed-lab/`의 C-AVATAR Feature/Profile/Row 예시는 **이미지 크기와 착장 합성** 시연이지 Big/Middle/Small의 전용 프리셋이 아니다. 실제 긴 이름·200%·장착 조합에서의 픽셀/포커스 검증은 별도이며, 시연만으로 합격 처리하지 않는다.

## Context-aware composition · 컴포넌트를 조합하는 방법

| 페이지 맥락 | 첫 시선 | 본문 구조 | 보조 행동 위치 | 피해야 할 것 |
|---|---|---|---|---|
| 일상 실행 / 퀘스트 | 오늘 상태·다음 한 행동 | 조밀하되 읽기 쉬운 List/Progress | 관련 행·섹션, 단일 완료 CTA | 카드마다 그림자·3D 코인·두 개의 상위 제목 |
| 발견 / 퀘스트북 | 관심을 끄는 실제 콘텐츠 이미지 | Media Frame + title + 작성/참여 메타 | 목록 header/카드 내 선택적 low | 모든 콘텐츠를 같은 흰 버튼 카드로 획일화 |
| 소셜 / 클랜 | 사람·활동과 의미 있는 현재 상태 | 동일 List Item + 아바타 + 시간/맥락 | row suffix 또는 section action | 클랜 채팅만 테두리 큰 시스템 메시지처럼 과장 |
| 개인 / 마이 | 사용자 정체성 + 실제 기록 | 투명 아바타 + 주요 숫자 1그룹 + 수집·링크 | 프로필 조작은 medium, 기록은 low | 120px 마스코트와 이름/인사말/보상 수치가 전부 hero |
| 진열 / 꾸미기 | 소품 이미지와 장착 여부 | 일관된 Image Frame grid + 짧은 라벨 | 컨텐츠 선택 후 필요한 행동 | 아이템 전부에 강한 그라데이션/발광 |
| 이벤트 / 수령 | 한정된 강조 아트·받은 결과 | A2/A3 Hero + 필수 정보 | 한 주 행동만 강하게 | 앱 모든 화면에 A3 배너 반복 |

**조합 전 순서:** 화면의 주목적 한 문장 → 가장 먼저 보여야 할 결과/콘텐츠 → 다음 행동 → 실제 데이터 슬롯 → 제목·보조정보 비율. 이미 고른 콘텐츠 수·카드 개수로 UI 위계를 역산하지 않는다.

## 불필요한 면 줄이기
1. Surface는 **정보가 같은 그룹**이어서 연결될 때 사용. 단순 간격으로 구분 가능하면 카드 제거.
2. 행이 반복될 때 아이템마다 개별 테두리·그림자를 넣지 말고 일관된 List/Divider를 우선.
3. Image Frame과 일반 목록의 배경을 한꺼번에 화려하게 채우지 않음. S2-03/06은 **콘텐츠 아트만** 입체적.
4. Tabs/Segmented/Sort는 데이터 영향 범위가 다르므로 UI상 같은 층에 밀어 넣지 않음.

## 비중 제안
일반 프로필은 [C-AVATAR](../components/avatar.md) size.avatarProfile, 행은 size.avatarRow를 쓴다. 최대 size.avatarHeroMax는 프로필 정체성 자체를 탐색하는 몰입 영역에서만 검토한다. 인사말·출석 설명·주간 보조 정보는 body/support로 시작하며 hero 크기를 자동 상속하지 않는다. 이미지의 큰 캐릭터·큰 인사말을 그대로 수치 사양으로 삼지 않는다.

큰 아트가 있는 배너는 문장을 짧게 하고 메시지와 액션의 안전 영역을 확보한다. 일상 페이지의 모든 섹션을 hero로 만들지 않는다. 첫 화면에서 '목적 / 현재 상태 / 다음 행동'을 설명할 수 있어야 한다. 이 세 항목을 고정된 카드 개수·순서로 오해하지 않는다.

## 탐색·필터·정렬의 층
상위 Tabs, 기간/보기 Segmented, 정렬은 서로 다른 층이다. 동일한 둥근 container 안에 모두 끼우지 않는다. 필터는 영향받는 리스트 옆에, 정렬은 리스트 Header의 보조 위치에 둔다. 모바일에서 세 종류를 한 줄에 억지로 배치하지 않는다.

## 밀도·확장
행·타일의 세부 문구가 길어지면 줄·높이를 허용하고 그리드 열 수를 줄인다. 보조 메타데이터를 줄일 수 있는지 먼저 판단하되 필수 정보는 숨기지 않는다. 동일한 슬롯으로 1개·많은 항목·긴 이름·긴 수치가 모두 유지되는지 확인한다. 서로 다른 출처 썸네일에는 Image Frame 규격만 공통 적용하고 그림을 획일화하지 않는다.

## 상태·근거·영향
빈·오류·로딩도 같은 그룹 구조를 유지하며 의미가 없는 empty Card를 여러 개 나열하지 않는다. 직접 관찰 high: 제목/아트/기록의 조합. 구체적 역할 한도·검수 조건은 proposed. REF-005 04/06/08/09의 과장·밀집·이탈을 교정한다. 데이터·메뉴 구조·친구 공개 범위는 제품 문서 정본의 미결 사항을 따른다.



## 2026-11-08 · 시연 검수에서 발견된 구성 경향 (proposed 보완)

**본 문서는 화면 배치를 복사하라는 설계도가 아님.** 서로 다른 정보 유형을 동일한 'Section Header → text rows → border → CTA' 템플릿으로 눌러 담는 구현을 막는다.

| 정보 원형 | 1차 시선 | 추천 조합 (기존 컴포넌트) | 반례/금지 |
|---|---|---|---|
| 클랜 정체성 | 깃발 + 이름 | C-AVATAR identity art + C-TEXT item + meta + C-ACTION compact | Root 타이틀 '클랜' 아래 같은 이름의 별도 대형 타이틀 반복, 인원수를 success badge로 강조 |
| 공동 보상 | 목적에 따라 값·아트·구성·결과 | 공동 기록=값+Progress, 홍보=A2 후보, 구성=정보 객체, 실제 획득=A3 후보 | 공동 보상이라는 이름만으로 A2·Reward Hero·진행 관리의 한 면 결합을 강제 |
| 구성원 활동 | 아바타/행동·시간 | C-AVATAR + C-LIST 단순 행 + 상태·메타 | 아바타 4명 요약과 같은 사실을 커다란 CTA·다중 제목으로 반복 |
| 커뮤니티 텍스트 피드 | 내용 제목 또는 질문 | C-LIST plain + Category chip + 본문/시간/반응 | 실제 콘텐츠 없는 대형 썸네일·강제 Card, 모든 피드에 같은 굵은 제목 |
| 미디어 피드 | 실재 사진·작품 | C-IMAGE + C-LIST media + item+meta | 원본 없는데 임의 이미지를 내용으로 가장하거나, 미디어·제목·상태를 모두 hero로 만듦 |
| 상세/댓글 | 대화 본문 | Identity meta + Content + Reaction + Comment, context별 Accent | 상단 헤더 제목, 본문 제목, CTA가 동급의 강조를 갖는 것 |

**반드시 서로 달라야 하는 것:** 1차 시선이 이미지인지 수치인지 텍스트인지. Plain/Media/Reward는 포장 스타일이 아니라 **정보의 역할**에서 결정한다.
**반드시 같아야 하는 것:** 기준선, Icon contract, 상태 의미, 타이포 5단 역할, 터치·접근성.

화면 리뷰에서는 1) 2초 내 주인공 한 개 2) 같은 문구 반복 3) 실제로 누르는 대상과 버튼 위계 4) 컴포넌트 선택 근거 5) 320/390/430px 캡처에서 한 번씩 따진다. 이 섹션은 기존 D-012의 수치 계약을 변경하지 않음.

> **2026-11-08 공통 계약 r1 적용:** 아래 절은 사용자 위임에 따라 이번 웹 개편의 기준으로 확정했다. 문서 전체의 과거 실험·제품 미결·Native 미검증을 일괄 승인한 것은 아니다.

## K05 정보 객체의 슬롯과 맥락

**정본 소유자:** `patterns/content-hierarchy.md`.

객체의 후보 슬롯은 Media / Identity / Value / State / Action이다. **Identity는 읽을 수 있는 이름을 포함하고, 나머지는 맥락과 실제 데이터가 필요할 때만 사용한다.** 미디어가 실패해도 이름·상태·행동을 해석할 수 있어야 한다.

| 맥락 | 필수 슬롯 | 조건부 슬롯 | 배제 |
|---|---|---|---|
| 보상 구성 | Media, Identity, 보상 구성이라는 상위 맥락 | 정의된 수량·조건·실제 상세 이동 | 구매 가격·장착 행동의 자동 삽입 |
| 상점 | Media, Identity, 실제 가격과 통화 의미 | 재고·구매 가능 상태·실제 구매/상세 | 장착 상태의 무조건 노출 |
| 보관함 | Media, Identity, 소유/장착 상태 | 로컬 선택·사용 제한·상세 | 반복 구매 가격 |
| 획득 결과 | 획득 사실, Media, Identity | 수량·확인/다음 행동 | 목록용 메타 전부 반복 |

이번 실증의 실제 제품 화면은 보상 구성이다. 상점·보관함은 예시 데이터가 명시된 독립 검수 fixture로만 사용한다. 예시 가격·소유·장착을 실제 정책이나 저장 데이터로 승격하지 않는다.

Media와 Information을 DOM 슬롯·간격·정렬로 구분한다. 분리선·서로 다른 배경색은 필수가 아니다. 같은 반복 모음에서는 미디어 비율·이름 시작선·값 기준선을 공유하고, 필요한 텍스트의 높이를 허용한다. 확대 시 열 수를 줄인다.

정적, 이동, 선택은 하나의 시점에 대표 상호작용 하나를 갖는다. 선택은 `aria-pressed` 또는 해당 선택 위젯의 상태, 이동은 링크 목적지로 표현한다. 소유·장착은 도메인 사실이며 선택 상태와 다르다. 원격 반영이 있다면 Pending/Confirmed/Failed를 별도 작업 상태로 다루고 선택만으로 장착 성공을 표시하지 않는다.

범용 ItemCard와 Composite 계층은 만들지 않는다. 실제 반복성과 독립 행동이 확인되면 기존 미디어/텍스트/액션 조합의 작은 구현 단위만 추출한다.

## S06 · 아이템 표현 A/B와 별도 인사이트 넘버 박스 (구성 패턴 제안)

**서로 다른 두 판단을 분리한다:** 아이템은 이미지/배지/정보가 **하나의 객체에 속하는가**, 인사이트는 서로 다른 수치를 **같은 기준으로 요약·읽을 수 있는가**가 핵심이다. 아래 A/B 및 넘버 박스는 신규 Component/Composite/Surface/Page Type이 아닌 **기존 정보 객체·레이아웃·표현의 조합**이다.

### A · 이미지 중심 아이템 / B · 이미지 + 내부 정보 패널

```text
A. 이미지 중심                  B. 한 개 외부 아이템 부모
[이미지 영역]                    ┌────────────────────────┐
[모서리 배지?]                   │ 이미지 영역  + 배지?    │
                                │  · · 내부 경계? · ·     │
                                │ 이름                   │
                                │ 설명·메타·카테고리?    │
                                │ 실제 가격/수량/상태?   │
                                │ 관련 Action?          │
                                └────────────────────────┘
```

- **A:** 이미지가 정보의 중심이면 기존 **C-IMAGE 프레임**과 선택적 Badge만으로 표현할 수 있다. *하단 정보 패널은 필수가 아니다.* 다른 목록·섹션에서 이름이 이미 전달되거나 이미지 선택 자체가 목적이면 중복 정보와 장식을 억제한다. 단, 이미지가 유일한 의미 정보라면 접근 가능한 이름/대체 설명을 확보한다.
- **B:** **외부 아이템 부모 1개** 아래에 `이미지 영역(C-IMAGE)`과 `정보 패널(Identity·Meta·Value·State·Action)`이 **형제 내부 영역**으로 속한다. 정보 패널을 부모와 떨어진 별도 Card, Solid, 독립 클릭 대상처럼 만들지 않는다. 내부 경계를 여백·색 차이·선으로 구분할 수는 있어도 **구분선·테두리·다른 배경은 선택**이다. 도식의 가로선은 CSS `border` 명세가 아니다.
- **B의 읽기 순서 후보:** **이름 → 선택적 설명·카테고리·메타 → 필요한 실제 가격/수량/상태 → 필요한 경우 Action**. 공간이 좁다고 중요 정보를 지우거나 가격을 배지로 바꾸지 않는다. 실제 소유·가격·장착·수령 여부는 상품의 **제품 맥락과 데이터 상태**에 따라 달라지는 선택 슬롯이다.
- **높이:** B의 정보 영역과 **외부 부모 높이는 콘텐츠 길이에 따라 늘어난다**. 텍스트·가격·버튼을 좁은 하단 패널의 고정 높이에 압축하거나 이미지 뒤로 겹치지 않는다. 이미지의 ratio·면적은 독립 선택할 수 있고 정사각형 도식/동일 높이를 강제하지 않는다. 기존 C-IMAGE의 `item` 기본 1:1을 임의로 전역 교체하지 않고, 다른 이미지 맥락의 비율 선택은 C-IMAGE와 P-LAYOUT에서 판단한다.
- **소유권:** C-IMAGE는 `fit=contain/cover`, 이미지 비율·로딩/오류/폴백·모서리 Badge만 소유한다. **가격·이름·설명·구매/장착 Action은 프레임 외부**이고 정보 객체/부모 조합이 소유한다. 수량/캐시 가격의 의미·코인 이미지는 [C-CREDIT](../components/credit-value.md), 보유/선택/장착 등의 상태는 C-STATUS 및 도메인 사실, 텍스트는 C-TEXT, 조작은 C-ACTION과 P-ACTIONS에 맡긴다. 이미지 로딩 실패에도 외부 이름/값/행동을 지우지 않는다. 전체 이동 링크 안에 별도 구매 버튼을 중첩하지 않는다.
- **구성 선택:** 책장형의 대표 아이템과 작은 아이템, 가로 흐름형 Rail 및 Grid에 A와 B를 조합할 수 있다. 큰 항목·작은 항목의 **이미지 비율/정보 길이 차이는 허용**하되 같은 모음의 이름·가격·메타 **의미와 기준선**을 일관되게 읽도록 한다. 책장형이 B만, Rail이 A만 사용해야 한다는 규칙은 없다.
- **검수 데이터는 실제 상품 정책과 구별:** 상점은 *실제 정의된 가격이 있는 경우에만* 가격/구매 여부, 보관함은 소유·장착 상태, 보상 구성은 보상 이름·수량/구성이라는 각 맥락을 가진다. 예시 `420 캐시`는 **가상 값**이지 실제 상점 가격·재화 지급 로직의 확정이 아니다. 실데이터 없는 임의 장착/소유 상태를 승인 상태로 보이지 않는다.
- **폭/확대 확인:** 320/360/390/430 폭, 200% 텍스트, 긴 한글 이름·긴 가격 숫자, 배지 있음/없음, 이미지 로딩/오류, Action 있음/없음의 대표 조합에서 **하나의 외부 부모**, 충분한 정보 영역 높이, 주요 내용 무손실, 가로 오버플로 0을 실제 렌더에서 확인한다. 그 검수가 되지 않았으면 문서 적용만 완료로 표기한다.

### B의 두 진열 표현 · 통합형과 오픈형 (2026-11-11)

**이미지 중심 A는 그대로 유지한다.** 다음 두 표현은 **B(이미지+외부 정보)**를 표시하는 방법이며, 새로운 ItemCard/Surface 종류가 아니다. 어느 쪽이든 미디어와 이름·가격·행동은 같은 아이템 부모에 귀속된다.

| 판단 | 통합 카드형 (사용자 레퍼런스 좌측) | 오픈 진열형 (사용자 레퍼런스 우측) |
|---|---|---|
| 주 사용 | 독립 상품 강조, 설명·구매/장착/선택 등 개별 행동 | 여러 상품의 빠른 탐색·비교, 행동 없는 그리드/레일 |
| 외부 경계 | 필요할 때 기존 Solid 등 **중립 1px 외곽선 하나**, radius 유지 | **Plain 우선**, 부모 테두리·카드 배경·그림자 없음 |
| 이미지/정보 | 같은 외부 면 내부에서 상단 이미지 배경과 하단 정보 배경을 구분할 수 있음 | **모서리가 둥근 이미지 배경만** 두고 이름·가격은 페이지 배경 위에 직접 표시 |
| 프레임 경계 | 전체 카드 border를 이미지 영역에 또 긋지 않음 | 이미지 영역 border는 기본값이 아니라 선택적 시각 보정 |
| 정보 | 이름 → 선택적 메타 → 실제 가격/상태 → 선택적 행동 | 이미지 → 외부 이름 → 실제 가격/상태, 행동은 필요할 때만 |

- **우선 권장:** 행동 없는 반복 상품 목록·격자는 오픈 진열형을 먼저 검토한다. **개별 상품에 버튼이 들어가면 통합 카드형 외부 컨테이너 사용을 권장**한다. 버튼 없이도 강조가 필요한 상품은 통합형 허용, 버튼이 있는 오픈형도 실제 디자인 이유가 있다면 금지는 아니다. 버튼 여부만으로 새 표면 역할을 정의하지 않는다.
- **가변 폭:** 두 표현 모두 기본 item 프레임의 **1:1 비율과 contain + 안전 여백**을 유지하며 폭을 따라 함께 줄거나 커진다. 상품 이미지 자체를 crop하거나 상품 카드 전체를 일정 가로세로 비율로 고정하지 않는다. 특별한 비정사각형 장면은 C-IMAGE에서 명시적으로 비율을 선택한다.
- **가변 높이:** 이름·가격·상태·설명·Action은 정보 영역의 **자연 높이**를 차지한다. 긴 한글 상품명은 줄바꿈, 큰 글자는 높이 증가로 대응. 숫자·가격·버튼을 고정된 30% 하단 칸에 압축하거나 이미지 위에 겹치지 않는다.
- **버튼 배치 (교정):** 기본은 **정보(이름·메타·가격/상태) 바로 다음의 정상 흐름**. `height:100%`, 정보 `flex:1`, CTA의 `margin-top:auto`를 기본 조합하지 않는다. 이 조합은 높이가 다른 **다른 열·형제 콘텐츠**가 카드를 늘리는 경우 가격과 버튼 사이를 벌려 상품 단위를 분해한다. 동일 행의 동등한 카드끼리 높이를 맞출 실질적 이유가 있을 때에만 별도 배치에서 검토하고, 그때도 정보 그룹과 Action의 시각적 근접성을 유지한다. 절대 위치/고정 오프셋 금지. 버튼 최소 48px 터치 영역과 줄바꿈을 보존한다.
- **정보 밀도·비례/정렬 (교정):** 이미지 아래 **Identity + 실제 Value**는 하나의 조밀한 정보 그룹이며 이미지/정보 사이보다 **이름/가격 사이의 간격을 작게** 잡는다. 이름·가격은 같은 진열 안에서 각자 역할과 읽기 순서를 유지하되 둘을 같은 강도로 과장하지 않는다. 이미지 비율·안전 여백·이름의 시작선·가격의 순서는 모음에서 통일한다. 긴 이름은 내용을 잃지 않고 늘어나며, 정렬만을 위해 빈 세로 공간을 생성하지 않는다. 열 수와 가로/세로 전환은 P-LAYOUT에 맡긴다.
- **상호작용:** 전체 상품 링크가 있으면 내부 구매 버튼을 중첩하지 않는다. 별도 행동이 필요한 카드는 정적 부모 아래 의미 있는 링크/버튼을 형제로 둔다. 상품 가격·소유 상태는 실제 데이터에서만 가져오며 시연값은 예시로 표시한다.

**실제 구현:** `seed/styles/seed-standard.css`의 `.seed-item-display` + 기존 `.seed-surface`/`.seed-media`/`.seed-text`/`.seed-credit`/`.seed-action` 조합. 이 클래스는 B의 내부 배치만 공유하고 새 SEED Component·Surface Variant·제품 정책을 생성하지 않는다. SEED Lab의 List & Media 아래 두 표현을 같은 원본 에셋으로 비교한다.

### S06 가로 통합형의 실제 결함 교정 · 2026-11-12

- **가로형의 이미지 패널은 카드 전체 높이를 채워야 한다.** 기존 시연에서 정사각형 1:1 배경만 왼쪽 상단에 붙어 그 밑이 흰색으로 남은 것은 반응형 예외가 아니라 잘못된 배치다. `data-item-presentation="integrated" data-item-layout="horizontal"`은 **이미지 패널의 배경을 전체 높이까지 연장**하고 `object-fit:contain`으로 상품 오브젝트의 원본 비율과 여백을 보존한다.
- **세로형**은 기본 정사각 프레임 1:1을 유지. 가로형의 배경 프레임은 카드 정보 높이에 맞춰 직사각형으로 바뀔 수 있지만 원본 이미지의 비율은 왜곡하거나 자르지 않는다. 정사각형을 억지로 유지하다 하단에 흰 공백을 만들지 않는다.
- 버튼·설명·가격의 순서는 동일한 Item Info 하나로 묶고 이미지와 정보가 서로 다른 카드인 것처럼 보이게 하지 않는다. 열 너비는 맥락별로 결정하되 기본 `--seed-item-media-share:40%`를 조정할 수 있다. 카드 높이 고정·CTA 바닥 고립·좁은 폭에서 글자 축소 금지. 레퍼런스 시연용 독립 HTML은 SEED 정본이 아니므로 `seed/styles/seed-standard.css`를 실제 소비한 후 검수한다.

### 상점 진열 조합 예시

- 390px 상점에서 가격과 대표 행동을 함께 보여줄 상품은 **가로 통합형** 한 장을 우선 검토한다. 이미지 패널은 카드 높이를 채우고, 이름·가격·행동은 정보 영역 안에서 이어진다.
- 일반 탐색 상품은 **3열 오픈형**에서 이미지·이름·가격을 가까이 묶는다. 긴 상품명·큰 금액·글자 확대에서 정보가 잘리거나 타깃 폭을 확보하지 못하면 2열 또는 세로 목록으로 전환한다. 비교 시에는 같은 상품과 가격을 사용한다.

### 인사이트 넘버 박스 · 아이템 카드가 아닌 수치 요약

```text
[     12     ]   [      9     ]   [     123    ]
[    완료    ]   [     진행   ]   [     누적   ]
```

- 각 통계 객체의 조합은 **대표 숫자(Value) + 짧은 아래 의미 라벨(Identity)**이다. 이 예시의 `12 / 9 / 123`은 실제 사용자 데이터나 새 제품 지표 정책이 아니다.
- 기존 C-TEXT의 **Display/number**와 의미에 맞는 **Caption/support 또는 Body**를 사용하고 `tabular-nums` 기준선으로 자릿수 차이의 흔들림을 줄인다. 기간·단위·비교 범위가 필요하면 이름을 명확히 덧붙이되 확인되지 않은 수치를 만들지 않는다.
- **열 수·너비·높이·Divider·Border·숫자 크기·색상·Surface는 모두 선택**이다. 2개·3개·4개 이상의 수치, `9`부터 `12,345`처럼 긴 자릿수에서도 라벨과 대응 관계가 보이도록 필요하면 줄바꿈·열 수 감소·세로 배치로 전환한다. 원본 도식선은 실제 CSS 테두리 지시가 아니다.
- 인사이트의 활동 건수/완료 건수 등을 **가격(C-CREDIT)이나 아이템 Image Frame로 구현하지 않는다**. 단위가 캐시인 경우에만 C-CREDIT의 실제 재화 표시 규칙을 확인한다. 숫자 카드마다 독립 구매 Action·상태 Badge·배경 Surface를 붙이지 않는다.
- **별도 검증 경계:** 320px·200% 확대, 1/2/3/4열 선택, 짧은·긴 라벨, 1~6자리 숫자와 미확인 값에서 넘침·기준선·스크린리더 읽기 순서를 확인한다. 문서의 규칙 명시는 픽셀 검증·앱 동작 승인과 다르다.

## S09 · 이벤트 표현과 형식 선택 (일반 Container의 새로운 종류 아님)

**이벤트는 정보 묶음의 외형이 아니라 콘텐츠의 목적**이다. 일반 Container/Section은 같은 정보를 묶는 관계이고, 이벤트 콘텐츠 영역은 **이벤트 존재를 알림·관심/참여로 유입·실제 진행/상태를 확인**하는 맥락을 먼저 판단한다. **목적·현재 페이지와의 관련성·일시성/시즌성·정보량·실시간 값 변경 여부·이동/페이지 안 실행**을 확인한 뒤 기존 C-SURFACE·C-IMAGE·C-STATUS·P-ACTIONS를 조합한다. 이벤트마다 같은 판촉 카드 템플릿을 복제하지 않는다.

**이벤트 배너 아트 금지사항:** **SVG로 이벤트 배너 내부 이펙트(광원·후광·광택·입자·입체 재질·3D 그림자)를 억지로 따라 만드는 것 금지.** 원본 배너 아트가 없으면 CSS/SVG 도형을 여러 개 쌓아 비슷한 연출을 꾸미지 않는다. 실제 준비된 완성 이미지/아트가 있으면 원본을 활용하고, 없으면 과장 없는 일반 Banner 또는 정보형 B를 선택한다. 공식 SVG 아이콘은 별도의 정보·행동 표시 목적으로만 허용하며 **이미지/이펙트 대체재가 아니다.**

### A · 얇은 일체형 이미지 배너 (완성 이미지 한 장)

```text
┌───────────────────────────────────────┐
│ 이미지 원본 한 장                      │
│ (문구·그래픽·장식이 이미지에 포함됨)   │
└───────────────────────────────────────┘
하나의 이미지 자체 또는 전체 링크 한 개
```

- **DOM 콘텐츠는 완성된 가로형 이미지 한 장**이고, 클릭이 필요하면 그 이미지 전체를 **단일 링크/이동 target**으로 감싼다. 이미지 위나 같은 배너 표면 안에 **독립 제목/설명/버튼/Badge/Progress/실시간 숫자 UI를 오버레이하지 않는다.** 이는 '기존 Banner의 모든 UI 금지'가 아니라 **이 형식을 선택했을 때만** 지키는 계약이다.
- 이미지에 있는 문구는 배너의 **아트 안에 이미 포함**되어 있다. 대체 텍스트 또는 링크 이름으로 핵심 메시지와 이동 목적을 알리고, 키보드 focus·48px 이상 터치 target·링크 목적지 유효성을 확인한다. 원본 텍스트나 인물/물체가 cover에 의해 잘리지 않도록 **가로 비율·원본 해상도·텍스트 안전영역**을 검증한다. C-IMAGE의 scene/thumbnail을 활용하되, 이 형식에서 허용되는 모서리 Badge/Overlay는 **사용하지 않는다**.
- **홍보/유입·짧은 안내/존재 알림에서 검토할 수 있다.** 실시간 포인트·진행률이 중요하면 이미지를 반복 갱신할 비용/주기를 검토하거나 B로 넘어간다. 시즌 행사라는 이유만으로 B를 강제하지 않는다.
- 구조 검수용 HTML **의사 예시(실제 에셋·라우트 아님)**: `<a href="{실제 이벤트 경로}" aria-label="{이벤트 내용과 이동 목적}"><img src="{완성된 가로 배너 원본}" alt="{이미지 핵심 내용}"></a>`. 내부 요소는 **이미지 1개**, 별도 Button·Progress·Badge·텍스트 노드 **0개**. 이 마크업이 실제 사용 가능한 페이지나 배너 자산이라는 뜻은 아니다.

### B · 박스형 이벤트 (선택적 동적 정보 조합)

- **이미지/오브젝트, 제목, 설명, 포인트·참여 인원, 참여 상태, 진행률, 보상, 행동은 각자 필요할 때만 사용**한다. `이미지+Progress+Button` 세 항목을 필수 세트로 묶지 않는다. 이미지가 없어도 유효하고, 진행률/CTA가 없어도 유효하다. 다만 **이벤트를 식별할 최소한의 의미 있는 콘텐츠**는 있어야 하며 빈 카드만 만들지 않는다.
- 값이 실제로 바뀌는 경우 **C-STATUS의 동일한 입력값/label/ARIA**에서 Progress를 렌더하고, 상태·포인트·참여 인원을 갱신한다. 의미 없는 임의 숫자·지급 확정·가짜 참여 버튼을 만들지 않는다. 이동 링크와 독립 실행 버튼은 역할을 구별하고 서로 중첩하지 않는다.
- **정보성 박스만 강제하지 않는다.** 필요하면 C-IMAGE scene과 A-ART의 A2 아트를 크게 사용할 수 있고, 필요 없는 텍스트·수치·Action은 제거한다. 아트가 크더라도 C-SURFACE의 Media/Reward, 가로·세로·격자 배치, 표면 강도는 목적별로 선택한다. 이미지 한 장 자체가 전체 내용이라면 B로 포장할 이유부터 재검토한다.
- **정보량과 높이는 유동적**이다. 참여율·남은 조건·포인트·보상이 한 패널에 과밀하면 페이지 목적에 따라 상세로 분리한다. U04의 '아이템 B 한 부모 이미지+가격'을 이벤트 박스의 필수 Anatomy로 전용하지 않는다.

### 요약형은 형식 C가 아니라 정보량 조절 전략

관련성이 낮거나 핵심 과업보다 우선도가 낮은 이벤트는 **배너 A 또는 박스 B 중 선택한 구조의 노출 면적·정보량을 줄인다**. 글자만 있는 짧은 안내·저강도 진입도 가능하며 반드시 이미지형으로 바꾸지 않는다. 요약형이란 새 Surface/Variant/세 번째 이벤트 컨테이너가 아니다. 관련성이 높아도 강한 상업적 배너 대신 조용한 동적 요약이 적절할 수 있다.

### 목적 판단 및 세 가지 검수 사례 (실제 기능 확정 아님)

| 상황 | 먼저 묻는 질문 | 합리적인 구성 후보 | 반례 |
|---|---|---|---|
| **유입·홍보** | 이 자리에서 핵심 메시지를 이미지 한 장으로 전달 가능한가 | 완성 아트가 있으면 **A** 전체 이미지 링크. 없으면 기존 Banner/텍스트 소개 사용 | 투명 오브젝트 A1 확대를 완성된 홍보 배너로 간주; 이미지 위에 실제 버튼·Badge 합성 |
| **페이지 관련 동적 이벤트** | 사용자에게 진행·참여 상태가 지금 유의미하며 실제 값이 갱신되는가 | **B**: 텍스트+실제 Progress만(이미지·버튼 없음), 또는 이미지+제목+실제 Action만(Progress 없음), 또는 맥락에 맞는 다른 선택 조합 | `이미지+Progress+Button` 필수, 박스마다 A2 강제, 모든 진행을 수령 완료로 오인 |
| **낮은 관련성의 요약** | 이번 화면의 주요 작업을 가리지 않고 이벤트 존재를 알릴 수 있는가 | **A/B를 축약**: 기존 작은 소개/저강도 이동, 관련성 낮은 데이터는 상세로 이동 | '요약형'을 세 번째 컴포넌트로 신설, 관련성 낮으니 무조건 이미지 배너 |

**정답 공식 금지:** `홍보=A` 또는 `상태=B`를 배타적인 공식으로 사용하지 않는다. 홍보에도 독립 UI가 필요하면 B를, 상태 안내라도 완성 이미지로 충분하면 A를 고려할 수 있다. **선택의 이유**와 제외한 불필요한 슬롯을 페이지 설계 기록에 남기고, 기존 전체 화면의 가장 중요한 콘텐츠와 경쟁하지 않는지 확인한다.

**기존 시연과의 대응 한계:** `web/preview/clan.js`의 `rewardPanel()`은 미디어·Progress·Action을 포함한 **복합 보상/공동 진행 표현** 예시일 뿐 모든 B의 필수 형태도, A 단일 이미지 배너도 아니다. `web/seed-lab/index.html`의 C-IMAGE/Progress 개별 시연은 선택 슬롯의 구성 재료를 확인할 수 있으나 **A 전체 이미지 링크 / B 선택 슬롯 생략 / 낮은 관련성 요약**의 3가지 실제 조합을 자동 검증하지 않는다. 브랜치 `assets/art/rewards/`에는 개별 보상 오브젝트만 존재하고 완성된 문구 포함 가로형 이벤트 배너 원본은 확인되지 않았다. 이 원본이 없으면 A의 실제 이미지·크롭 실증은 **미검증**으로 남긴다. 실제 샘플 페이지에서 A의 이미지 노드/링크 1개와 오버레이 0, B의 독립 슬롯 누락 조합, 320/360/390/430 폭·200%·라이트/다크·링크/키보드 접근성까지 별도로 확인해야 한다.

## 2026-11-10 · 공간 배치와 정보 위계의 접점 (추가 제안)

이 문서는 **무엇을 먼저 읽고 어떤 관계로 보여줄지**를 소유한다. 새로운 [공간 배치 규격](layout-composition.md)은 **그 관계를 세로·가로·격자·겹침의 어떤 위치 규칙으로 표현할지**를 소유한다. [페이지 구성 지침](page-composition.md)은 페이지의 섹션 경계·선택 순서와 실제 행동 목적지를 결정한다. 셋은 별도 계층이 아니라 동일한 Pattern 범주 안의 서로 다른 책임이다.

- 이미지/숫자/텍스트 중 무엇을 첫 시선으로 둘지 결정한 후에만 공간 배치의 강조 비율을 선택한다.
- **섹션 정의**와 **Surface 선택**은 다르다. 정보 목적이 하나인 섹션도 Plain으로 구성할 수 있고, 큰 Card 하나가 목적 여러 개를 합치는 면죄부가 아니다.
- '랭킹·이벤트·보상'과 같은 콘텐츠명이 레이아웃 타입이 아니다. 수치 비교 랭킹은 반복 List+세로 관계, 미디어 발견 랭킹은 Rail이 적합할 수 있다.
- 기존 정보 객체의 Media/Identity/State/Value/Action 슬롯을 Layout으로 대체하지 않는다. 같은 모자의 상점/보관함/획득 결과는 배치가 같아도 표시 의미가 다를 수 있다.
- **검토 반례:** 하나의 공동 보상 Hero에 이벤트 카피, 실제 진행, 구성 목록과 여러 강한 CTA가 경쟁한다면 CSS height 전에 목적·섹션을 다시 판단한다. A1 오브젝트를 확대한다고 A2 장면이 되지 않는다.

이 항목은 D-012 컴포넌트 스타일이나 D-013 기존 공통 웹 어댑터를 변경하지 않는다. 구체 페이지 배치의 최종 채택은 실제 화면에서 결정한다.
