# SEED r3 · Page Composition Protocol

## 현행 계약

Page를 만들 때는 **과업→목적→객체→부품**이다. 각 산출물은 `docs/design/pages/<page>.md`의 같은 이름 섹션으로 기록한다. 컴포넌트만 바꾸면 그 Component와 직접 의존만 확인한다.

| 단계 | 결정 | 고정 기록 섹션 | Gate |
|---|---|---|---|
| 01 | Page Intent 9필드: 유형/동사 과업/목적/주연/대표 행동/핵심 데이터/보조 데이터/다른 화면 책임/제외 이유 | 01 Page Intent | G1 |
| 02 | 사실의 의미, 현재/파생, 실제/시연, 중복, 대상 행동 | 02 콘텐츠·행동 인벤토리 | G2 |
| 03 | O-* 슬롯, 그룹·경계·화면 이동 | 03 객체·정보 구조 | G3 |
| 04 | 기존 Pattern·Component·Variant의 채택/배제 근거 | 04 선택·배제 근거 | G4 |
| 05 | 주연과 면적·밀도·아트·타이포/표면 대비 | 05 시각 위계 | G5 |
| 06 | 실제 코드·토큰 사용·예외·기능 보존 | 06 구현·회귀 | G6 |
| 07 | 실제 P4 5축, 스크린샷, 오류·복귀·미검증 | 07 검증·반례·복귀 | G7 |

### G1~G7 판정 질문

| 게이트 | 질문 | 실패 반환 |
|---|---|---|
| G1 목적 | 주연·대표 행동 각각 **정확히 1개**? 제외 목록이 있나? | 01 |
| G2 콘텐츠 | 데이터 2회 이상 반복이면 서로 다른 의미를 **한 문장**으로 설명할 수 있나? | 02 |
| G3 구조 | 모든 정보 객체는 O-* 스키마로 설명되고 클릭 책임이 명확한가? | 03 |
| G4 선택 | 부품마다 배제한 경쟁 후보와 그 이유가 기록됐나? | 04 |
| G5 시각 | **390×844 첫 뷰포트**에 주연이 나타나고 보조보다 강한가? | 05, 역할 오류면 **01** |
| G6 구현 | 공통 Variant/Token 우회한 지역 스타일이 **0개**인가? 예외는 승인/영향 기록했나? | 04~06 |
| G7 검증 | **실행/규격/객체·조합/목적/행동·회귀** 5축을 독립 판정했나? | 07 |

### 수정 위치 판정 다섯 단계

1. 규칙 존재·구현 위반 → 구현과 작업 절차부터 바로잡는다.
2. 규칙을 지켜도 목적에 맞는 부품 선택 불가능 → 기존 Pattern/Object/Component 선택·관계 계약 보강.
3. 승인된 규격 자체가 과업을 저해 → 반례·대안·기존 기능 영향으로 SEED 개정 **제안**, 임의 승인 금지.
4. 새 부품으로 보이지만 기존 결합으로 가능한가 → 최소 2개 페이지 반복 전 신규 공용 부품 생성 금지.
5. 코드 실행은 되지만 목적·의미·주목도·행동을 비교 못했나 → G7 미통과.

### R-01 의무 재현

**실패 관찰:** image7에서 Hero의 대형 A1 상자·홍보 카피가 `620/1000`과 사람 활동을 아래로 밀었다 → **G5 실패** → `Hero 높이를 줄인다`가 아니라 **G1 복귀**. 목적 '함께 움직임에 반응'과 주연 '공동 기록+사람 활동 그룹', 대표 행동 '행 응원' 확정 → G2 '6명' 3중 표기를 같은 정보로 판정 → G3 O-PROGRESS와 O-PERSON-ACTIVITY 분리 → G4 홍보 Hero와 아이템 타일 배제 → G5 390×844 재검증. 계약/화면 측정 없이 G5 성공이라고 표시할 수 없다.

실제 **구현 커밋에는 Page Record 경로 링크를 포함**한다. 단순한 문서량·코드 실행 성공을 프로젝트 게이트 통과로 착각하지 않는다.
