# 마이·꾸미기 균형 조정

기준: 사용자가 제공한 모자 합성·마이·꾸미기·구매 시트 실기기 사진.

- 모자는 얼굴 기준 폭 .80→.75, 높이 .55→.48, 위쪽으로 .025 이동. 헤드폰은 귀 바깥쪽을 감싸도록 폭 .98→1.02, 시작점 .12→.10 조정. 원본 PNG는 변경하지 않는다.
- 마이: 얼굴 영역 144→120dp, 가로 비중 48→39%, 이름 25→22sp, 꾸미기 동작 40dp 이상. 캐시는 작은 16sp 보조 지표, 기록과 섹션 제목은 굵기로 구분한다. 도장 슬롯은 낮춰 세로 밀도를 줄인다. 큰 글씨·좁은 폭의 세로 전환은 유지한다.
- 표식: `companion/ClanEmblem.kt`에 별 아이콘과 현재 연두색 팔레트를 등록한다. `toSvg()`로 SVG를 생성한다. `ui/ClanMark.kt`의 네이티브 렌더러도 동일한 경로·색상 데이터를 읽는다. 클랜과 마이 모두 이 컴포넌트를 사용한다. 표식 크기는 사용 위치에 맞추되 그림은 동일하다.
- 꾸미기: 미리보기 비율 1.72→2.15, 얼굴 최대 192→152dp, 상품 그림 비율 1.58→1.8, 가격 20→16sp. 보유 상품을 누르면 미리보기만 바뀌고 하단 ‘적용하기’로 저장한다. 미보유 상품은 구매 시트를 열며 구매 후에도 적용은 별도다. 빨간 테두리는 미리보기 선택, ‘착용 중’ 배지는 저장된 항목을 뜻한다.
- 구매 시트: 상품 그림→가격→보유 캐시/구매 후 잔액→안내 순서로 정리한다. 버튼 문구는 상태와 관계없이 ‘구매하기’를 유지한다. 잔액 부족·처리 중·보유 상태에서는 비활성화하고 이유는 내용에 표시한다. 공통 시트의 선택적 footer 영역을 사용하고 드래그 위치에 따라 보이는 높이 안에 고정한다.

확인 범위: 기존 데이터/가격/DB 식별자를 보존한다. APK 빌드와 기존 구매 정책 회귀 테스트를 실행한다. 사용자 지시대로 에뮬레이터를 실행하지 않으므로 최종 시각적 균형, 모자 합성 위치, 반열림/펼침에서의 버튼 위치와 키보드 동작은 실제 기기 미검증이다.

소스 검토: 별도 검토자가 구매 후 착용 상태 보존, 보유 상품 미리보기/적용, SVG·네이티브 경로/색상 일치, 시트 외부 높이 고정으로 앵커를 유지하는 구조를 확인했다. 미리보기 접근성 문구가 현재 착용을 뜻하던 문제는 ‘선택한 아바타 미리보기’로 고쳤다. 시트의 창 높이/드래그 오프셋 기반 footer 배치는 실제 기기에서 확인해야 한다.

최종 검증: `assembleDebug`와 `testDebugUnitTest` 성공, 기존 단위 테스트 12개 실패·오류·건너뜀 0개. 접근성 문구 수정 후 최종 APK도 다시 빌드했다. 로그는 개발 환경 `/workspace/balance-final.log`, `/workspace/balance-apk-final.log`에 있다. 실제 기기 실행은 하지 않았다.

main에 먼저 추가된 얼굴 원본 교체(`15ff129`)도 보존하여 통합했다. 이미지 비율은 같은 범위이며 변경된 PNG를 포함한 APK 리소스 빌드가 성공했다(`/workspace/balance-integrated.log`).
