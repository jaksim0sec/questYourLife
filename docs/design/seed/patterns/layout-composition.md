# 공간 배치와 섹션 구조

> **범위:** 기존 SEED Pattern의 공간 배치 규격. 새로운 Component, Composite, Page Type, 런타임 라이브러리 또는 화면별 전용 컨테이너를 만드는 문서가 아니다. 이 문서의 네 가지 기본 배치와 속성은 이번 개편의 **설계 제안**이며 기존 v0.15의 확정 토큰·SVG·컴포넌트를 대체하지 않는다. 페이지 결정은 [페이지 구성 절차](page-composition.md), 기본 치수는 [간격·크기](../foundations/geometry.md)를 따른다.

## 1. 무엇을 추상화하는가

레이아웃은 **내용의 종류**가 아니라 **자식 요소들의 공간 관계**를 정의한다. 랭킹, 퀘스트, 이벤트, 상품, 프로필은 레이아웃 이름이 아니다. 같은 정보를 다른 목적과 밀도로 표시하면 다른 배치가 합리적일 수 있다.

- **섹션:** 페이지 안에서 한 가지 정보상 책임을 가진 의미 단위. 제목·본문·보조 행동이 선택적이다. 섹션이라는 이유만으로 카드·배경·테두리를 만들지 않는다.
- **그룹:** 섹션 내부의 가까운 정보·행동 단위. 하나의 그룹이 독립된 섹션으로 승격되는지는 목적·탐색·강조의 독립성으로 결정한다.
- **공간 배치:** 섹션이나 그룹의 자식들을 배치하는 네 가지 범용 규칙. 여러 단계 중첩할 수 있다.
- **표면:** Plain/Solid/Media/Reward 등 경계와 시각 강도. [Surface](../components/surface-media.md)가 소유하며 공간 배치 타입이 아니다.

### 책임 분리

| 판단 | 정본 소유자 | 배치 규격이 하지 않을 일 |
|---|---|---|
| 상단·하단·스크롤·safe-area·고정 CTA | [Page Shell](../shells/page-shells.md) + 확정 Top Navigation | 페이지마다 헤더/내비게이션 재정의 |
| 페이지 안 섹션 및 자식의 위치·크기 관계 | **이 문서** | 특정 콘텐츠 종류로 레이아웃 고정 |
| 그룹의 배경·경계·그림자·반경 | [Surface](../components/surface-media.md) | Stack/Grid에 자체 카드 스타일 강제 |
| 이미지의 비율·contain/cover·fallback·이미지 내부 상태 슬롯 | [Image Frame](../components/image-frame.md) | 이미지 위 배지마다 새 Layer 추가 |
| 개별 행·버튼·탭·Progress·텍스트 역할 | 해당 기존 Component | 해당 컴포넌트 내부를 이중 배치 규격으로 덮기 |
| 3D 보상·장면의 광원·표현 수준 | [Reward Art](../assets/reward-art.md) | 큰 사진만 넣으면 A2로 간주 |
| 어떤 섹션이 먼저·얼마나 강조되는가 | [페이지 구성 절차](page-composition.md) + [정보 위계](content-hierarchy.md) | 화면 목적·순위를 임의로 결정 |

## 2. 배치 공통 계약

**구성:** Parent boundary → children → 배치 방향/크기 관계 → gap/align/overflow → 반응형 전환. 새로운 시각 토큰을 여기서 선언하지 않는다.

| 공통 속성 | 의미 | 기본 판단 |
|---|---|---|
| Gap | 형제 요소 간 거리 | [F-GEOMETRY](../foundations/geometry.md)의 inline/item/group/section 관계를 사용. 자의적인 7px·19px 증식 금지 |
| Align | 교차축 정렬 | 시작·중앙·끝·늘림 중 읽기 기준선과 내용 크기로 선택 |
| Sizing | 고정 최소/내용만큼/남은 공간 채움/가중 비율 | 본문의 최소 가독 폭과 이미지 비율을 보존. 남는 공간을 강제로 콘텐츠 확대로 채우지 않음 |
| Overflow | 보임/줄바꿈/스크롤/자르기 | 필수 정보와 주행동을 잘라내지 않음. 가로 스크롤은 다음 항목 존재를 인지 가능하게 함 |
| Density | 그룹의 간격과 정보량 | 같은 정보의 스캔·비교 필요성으로 선택. Compact가 작은 글씨를 뜻하지 않음 |
| Breakpoint | 화면 폭·글자 배율에 따른 배치 변경 | 320/360/390/430 논리 폭과 글자 200%에서 필요한 정보 유지. 단순 열 수 고정 금지 |

## 3. 기본 배치 네 가지

### 3.1 세로 배치

**목적:** 순서대로 읽거나 비교할 요소를 위에서 아래로 배열. 콘텐츠 이름과 관계없다.

- **Anatomy:** Children → vertical gap → optional dividers; 전체 폭 또는 내용 폭.
- **주요 속성:** gap, align, width, divider policy, max visible items + 명시적 더 보기.
- **변형:** Loose(섹션 흐름), Regular(항목 그룹), Divided(비교 가능한 반복 행).
- **선택:** 사용자가 행을 차례대로 스캔하거나, 항목 간 숫자·상태를 같은 기준선에서 비교할 때.
- **피할 것:** 반복 행을 모두 개별 Elevated Card로 만들기; 마지막 행까지 불필요한 Divider; 짧은 항목에 과한 세로 면적.
- **Component 경계:** 행 내부의 아바타/본문/접미 숫자 정렬은 기존 [List Item](../components/list-item.md) 슬롯으로 우선 해결한다. 세로 배치는 **행들의 관계**만 결정.

### 3.2 가로 배치

**목적:** 함께 읽는 요소를 한 축에 두고 폭·비중·정렬을 조절.

- **Anatomy:** Children → horizontal gap → width allocation → alignment.
- **주요 속성:** content-sized / equal / weighted width; start/center/end/space-between; wrap; overflow.
- **변형:** Fit(내용 크기), Equal(동등 폭), Weighted(대표+보조), Rail(가로 스크롤).
- **선택:** 아이콘+텍스트+동작, 이미지와 설명의 병렬, 동등한 두 통계, 이미지 중심의 탐색 카드 연속.
- **Rail 조건:** 여러 항목을 **순차 탐색**하는 가치가 있고 한 화면에 다 펼치면 미디어·제목 가독성이 손상될 때. 개별 썸네일의 외형은 Image Frame이 소유.
- **피할 것:** 320 폭에서 두 긴 본문을 병렬로 강제; action 최소 타깃 침범; 각 아이템에 불필요한 독자 스크롤; Rail 안의 주행동 잘림.
- **관계:** Split은 기본적으로 Weighted의 조합이고 Rail은 가로 배치의 overflow 변형이다. 별도 레이아웃 계열로 먼저 승격하지 않는다.

### 3.3 격자 배치

**목적:** 서로 비교 가능한 반복 요소를 행·열에 따라 탐색.

- **Anatomy:** 반복 Children → cell width/height contract → columns → gap → reading order.
- **주요 속성:** 최소 셀 폭, 열 개수 또는 자동 열 계산, 비율, span(필요할 때), 행간.
- **변형:** Equal Cells, Adaptive Columns, Selective Span.
- **선택:** 아이템·썸네일이 비교의 핵심이고 사용자에게 **동시에 여러 후보**를 보여줄 때.
- **피할 것:** 참고 이미지가 3열이라는 이유로 모든 폭에 3열 강제; 긴 이름·가격 삭제; 셀마다 다른 미디어 비율로 정렬 붕괴.
- **경계:** 프레임의 내부 이미지/가격/장착 표시 관계는 C-IMAGE·C-CREDIT·C-STATUS 또는 해당 정보 객체의 조합 계약에서 결정. Grid 자체는 상품이라는 뜻을 모른다.

### 3.4 겹침 배치

**목적:** 기준 영역 위에 다른 요소를 **공간적으로 겹쳐야 할 이유가 있을 때** 배치.

- **Anatomy:** Base / Foreground / Anchor / Safe Region / Interaction order.
- **변형:** Background scene with readable foreground, anchored corner control, constrained overlap.
- **선택:** 실제 콘텐츠의 시각 표현이 중심이고 제한된 제목·상태·행동을 한 장면으로 결합해야 할 때.
- **피할 것:** 표·진행·반복 보상·링크를 한 이미지 위에 누적; 장식 위해 긴 문장 중첩; 터치 영역끼리 겹치게 하기.
- **소유권 예외:** **Image Frame 자체의 상태 배지·모서리 Overlay는 C-IMAGE를 우선**한다. 전용 Layer를 새로 감싸지 않는다.
- **A1/A2 구분:** 보상 오브젝트 A1의 크기 확대가 A2가 되지 않음. 장면 구도·텍스트 안전영역은 A-ART 정본.

## 4. 섹션을 감싸는 규칙

섹션은 콘텐츠의 **의미 경계**이지 꼭 시각적 박스가 아니다.

- 하나의 목적·결과·관련 행동을 함께 읽어야 할 때만 같은 섹션으로 묶는다.
- Header(선택): 제목 / 부제 또는 맥락 / 보조 이동. Body(필수): 네 가지 배치 중 하나 또는 기존 독립 컴포넌트. Footer(선택): 관련 조작. **빈 슬롯 때문에 자리를 예약하지 않는다.**
- Surface는 기본으로 Plain을 먼저 검토한다. 동일 목적 정보가 면으로 묶여야 할 때만 Solid/Outlined/Subtle을 선택한다. 독립 미디어, 보상 강조는 기존 Media/Reward의 제한을 따른다.
- 같은 섹션에 목록과 가로 진열이 함께 있다면 Section → Stack → 두 개의 하위 그룹(각자의 Layout)으로 표현한다. 모든 중첩이 새 Section은 아니다.
- 내용이 바뀌어도 레이아웃 타입은 유지할 수 있다. 다만 목적이 다르면 섹션 자체를 분리한다.
- 섹션 간 간격, 섹션 내부 간격, 행 내부 간격을 혼동하지 않는다. F-GEOMETRY의 section/group/item/inline 규격을 따른다.

## 5. 선택 알고리즘과 배제 규칙

**입력으로 먼저 관찰할 것:** (a) 요소 간 순서와 비교 관계, (b) 주연이 텍스트/숫자/이미지 중 무엇인지, (c) 동시 노출 개수와 반복성, (d) 세로/가로 탐색 의도, (e) 최소 읽기 폭과 상호작용.

1. **하나의 읽기 순서/비교 표준이 필요한가?** 세로 배치 + 기존 List 조합부터 검토.
2. **병렬로 읽어야 하는 소수의 요소인가?** 가로 배치 Fit/Equal/Weighted 검토. 좁아지면 세로 전환 가능해야 함.
3. **동일 크기의 여러 이미지를 한 번에 비교하는가?** Grid. 한 시점에 소수만 강조하고 연속 탐색하면 Rail.
4. **실제 이미지 장면과 앞쪽 정보가 하나의 공간을 공유해야 하는가?** 겹침. 정보가 많으면 분리하고 공간 중첩을 포기.
5. **이미 컴포넌트 자체에 슬롯/정렬/Overlay가 있는가?** 상위 Layout 신규 정의보다 기존 Component의 계약 우선.
6. **경계가 필요하다고 생각되는가?** 먼저 간격/Divider로 관계를 읽을 수 있는지 확인한 뒤 Surface 선택.

**중요:** 이 결정 트리는 정답이 하나라는 규칙이 아니다. 목적이 다른 동일 데이터(수치 비교 랭킹 vs 미디어 콘텐츠 탐색 랭킹)는 다른 결과를 내야 한다.

## 6. 재사용·반례 (참고 이미지에서 관찰된 관계)

| 참고 화면 · 실제 관찰 | 공간 분해 후보 | 섣불리 표준화하면 안 되는 것 |
|---|---|---|
| 11541 시즌 패스: 단계 보상이 연결되어 가로 연속 배치 | 가로 배치 + 상태/진행 관계(기존 컴포넌트 필요 여부 확인) | '시즌 패스 컨테이너', 새 결제 기능 |
| 11537 홈: 급상승 콘텐츠가 일부 보이며 오른쪽으로 이어짐 | Rail + Media Card/Image Frame | '랭킹은 반드시 Rail' |
| 11537 퀘스트: 좌측 썸네일과 우측 정보의 비대칭 비중 | 가로 Weighted + 기존 Media/List | '퀘스트북 전용 Split 컴포넌트' |
| 11535 DM: 위아래 메시지와 좌우 정렬, 제안서 내부 하위 배열 | 세로 배치 + 각 메시지 정렬 + 기존 조합 | 채팅 화면 전체를 단일 Container로 취급 |
| 11539 클랜: 기여도는 세로 행, 보상은 가로 진열 | 같은 Shell 안에서 다른 레이아웃 선택 | '클랜 전용 레이아웃' |
| 11454 꾸미기: 상품들은 균일한 3열 그리드, 상단 배너는 이미지 장면 | Grid + 별도 Layer/Media | 상품 종류에 따라 Grid 유형 복제 |
| 11432 네이버웹툰: 상단 인기 순위는 Rail, 본문 작품 탐색은 Grid | 같은 콘텐츠 카드의 다른 배치 목적 | '랭킹/추천/작품' 콘텐츠명으로 구조를 고정 |

위 항목은 **사용자가 제공한 이미지에서 관찰한 구조와 모델의 추출 후보**다. 원본 서비스의 내부 구현이나 사용자 실험으로 검증된 보편 규칙을 뜻하지 않는다.

## 7. 페이지별 자유도

- **변경 금지:** D-011 Top Navigation; D-012 컴포넌트·56 SVG·토큰; Shell safe-area/scroll 소유; 승인된 버튼/타이포/상태 의미.
- **허용 변형:** 실제 콘텐츠에 적합한 네 가지 배치 선택, 내부 비율·순서·스크롤·열 수·Section 채택 여부, 기존 Surface의 허용 Variant.
- **근거가 있어야 하는 예외:** 첫 화면 대형 면적 점유, 주행동과 같은 강도의 보조 CTA, 정보가 많은 Overlay, 표준 컴포넌트 슬롯 우회, 새 배치 유형 추가.
- **추가 금지:** 페이지 이름을 붙인 Layout 기본 타입, 별도 에디터용 schema, 실제 사용처 없는 토큰/variant, 앱 기능·경제·IA의 임의 확정.

## 8. 개발 연결

이 문서는 지금 당장 새 Layout 런타임 API·CSS 클래스·Compose 래퍼를 강제하지 않는다. 기존 웹 공통 클래스 계약([v0.15](../implementation/v015.md))을 보존하고, **실제 구현에서 동일 구조가 반복될 때** CSS 레이아웃 유틸리티나 Compose 조합을 재사용 대상으로 추출한다. 표현 토큰을 페이지마다 새 CSS로 덮는 건 금지하되, 내용별 열 수·가중 비율 등 배치 매개변수는 페이지의 책임으로 둔다.

시연/앱 코드 수정·컴포넌트 재구현·새 에셋 등록은 이 문서 작성의 완료 조건이 아니다. 설계안의 채택은 실제 여러 페이지 비교 후 결정한다.
