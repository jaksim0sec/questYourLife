## 문서의 상태 구분

- **[원칙]** 사용자가 직접 설명·정정한 제품 의도. 디자인 합의의 기준이며 화면별 상세 기능을 뜻하지 않음.
- **[구상]** 사용자가 원하는 경험 및 예시. 구체적인 동작·조건·운영 정책은 미확정.
- **[해석]** 위 발언을 체계화한 설명. 새로운 요구사항으로 강제하면 안 됨.
- **[미결]** [OPEN.md](../OPEN.md)에서 따로 논의할 사항.

각 문서의 인용문은 가능하면 **사용자의 원래 표현을 그대로** 옮겼음. 철자/구어체 또한 표현 보존을 우선했음. 인용문 외 본문은 구조화된 요약임.

## 변경 원칙

1. 제품 철학·사용자 발언을 제품 문서에, **미합의 기능 메커니즘**을 OPEN에 분리.
2. 후속 설계는 이 문서들의 **목적**을 존중하되, 세부 UI·화면 배치·경제 수치를 임의로 확정하지 않음.
3. 현재 브랜치는 문서화 전용. Android·백엔드·기존 그래픽 파일을 수정하지 않음.
4. 기존 README/IDEA/AGENT와 철학이 충돌하는 경우 코드 작업 전에 **명시적으로 정책 우선순위를 갱신**해야 함.
