# 상태별 표현과 피드백

## 경계
정지 컨셉은 대체로 populated/default 상태만 보여 준다. 아래 상태는 재사용 시각 시스템을 완성하기 위한 제안이며 백엔드 동작·경제 정책을 새로 확정하지 않는다. 상태 전이는 실제 도메인·API가 담당하고 UI는 확인된 결과를 표현한다.

| 조건 | 표현 | 허용 행동·주의 |
|---|---|---|
| 초기 로딩 | 기존 슬롯 크기의 Skeleton + 필요한 로딩 안내 | 가짜 데이터·달성률 금지 |
| 일부 갱신 | 기존 내용 유지 + 국소 busy | 페이지 전체를 매번 Skeleton으로 교체하지 않음 |
| 처음 이용·빈 목록 | 짧은 설명 + 의미 있는 다음 행동 | 빈 상태를 오류로 취급하지 않음 |
| 조회 실패 | 해당 영역의 오류와 재시도 | 다른 정상 영역까지 차단하지 않음 |
| 오프라인·캐시 있음 | 읽을 수 있는 내용 + 갱신 시점/오프라인 표시 | 서버 최신 결과로 위장하지 않음 |
| 오프라인·실행 불가 | 현재 제한 이유 + 연결 후 가능한 행동 | 성공·보상 확정을 미리 표시하지 않음 |
| 요청 대기 | 동일 버튼/항목의 pending + 중복 방지 | 동기화 가능 여부는 기존 구현 사실 확인 |
| 작업 성공 | 실제 상태 갱신 + 짧은 피드백 | 매번 큰 축하 모달을 강제하지 않음 |
| 실행 오류 | 가까운 오류 문구 + 재시도/복구 | 사용자가 입력한 값 보존 |
| 보상 미수령 / 확인 대기 / 수령 완료 | 서로 다른 라벨·아이콘·실행 가능 상태 | 체크/아트 연출만으로 지급 사실 단정 금지 |
| 취소 / 되돌리기 | 실제 지원할 때만 Low Action·결과 피드백 | 되돌릴 수 없는 행동에 가짜 Undo 금지 |
| 잠김 / 만료 / 권한 부족 | 각각의 이유와 가능한 다음 단계 | 모두 Disabled 회색으로만 뭉개지 않음 |

## 선택 규칙 · SEED Loading 공식 가이드와 구별
[SEED Loading Pattern](https://seed-design.io/patterns/loading)은 짧은 대기는 Progress Circle, 예상 레이아웃이 있으면 Skeleton, 실제 진행 비율이 있으면 determinate를 구분한다. 이 시스템도 **'어떤 데이터/범위가 로드되고 있는가'** 먼저 판단한다.

| 상황 | 선택 | 전환 · 예외 |
|---|---|---|
| 거의 즉시 끝나는 짧은 로컬 전환 | 별도 spinner 없이 직접 상태 반영 | 깜빡이는 로딩 UI를 오히려 추가하지 않음 |
| 특정 버튼만 서버에 제출 | 해당 버튼만 busy, 레이블/너비 유지 | 성공 전 확정 금지; 실패 시 원상복구+메시지 |
| 구조가 분명한 목록 최초 로딩 | 같은 슬롯의 Skeleton | 내용이 준비되면 자리 이동 없이 실제 행으로 치환 |
| 기간을 알 수 없는 작은 영역 조회 | Progress Circle + 영역 설명 | 전체 페이지를 가리지 않음 |
| 실제 진행량이 알려진 업로드 | determinate Progress + 수치 | 근거 없는 % 추정 금지 |
| 오프라인에 읽기 캐시 있음 | 현재 콘텐츠 + '오프라인/갱신 시점' | 완료·보상 수령 결과를 서버 확인 사실로 표시 금지 |
| 오류·재시도 | 해당 그룹 내부의 간결한 오류/Retry | 입력값 보존, unrelated group 유지 |
| 수령 대기→확정 | pending→확인된 값/소품 표시 | 단순 아트 애니메이션을 지급 증빙으로 사용하지 않음 |

**전환 흐름:** idle → pending → success / failure / cancelled. retry는 pending으로 돌아간다. unsupported undo는 표시하지 않는다. 시간 임계값·애니메이션은 백엔드 성능·실기기 결과로 검증 전 proposed.

## 표현 일관성
로딩·오류·선택·완료에 별도의 임시 글자 크기·색·radius를 만들지 않는다. 상태를 색 + 라벨/아이콘/문맥으로 중복 전달한다. Loading은 disabled와 구분하고, 완료는 애니메이션보다 실제 상태를 먼저 읽을 수 있게 한다.

## 접근성·모션
중요 결과는 스크린리더에 알리되 초 단위 중간값을 계속 읽지 않는다. Dialog 외 결과 메시지가 초점을 임의로 이동하지 않는다. 동작 줄이기에서도 완료·오류·수령 상태는 남는다. 로딩이 끝날 때 콘텐츠 점프를 최소화한다.

## 검증·영향
각 상태의 대상 컴포넌트·전제 데이터·행동·예상 피드백을 구현 fixture로 연결해야 한다. 문서의 상태 행이 존재하는 것과 실제 오프라인·지급·복구 기능이 동작하는 것은 별개다. 이번 작업은 시각 사양이며 실제 동기화/보상 E2E는 수행하지 않았다.
