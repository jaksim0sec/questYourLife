# 꾸미기 O-ITEM 맥락 Fixture · P3 Page Record

> [SEED PROCESS](../seed/PROCESS.md) · [4유형](../seed/pages/page-types.md) · [21개 계약](../seed/INDEX.md). 웹 Preview는 픽션 데이터이며 실제 지급·가입/구매 저장을 구현하지 않는다.

## 01 Page Intent

| 필드 | 결정 |
|---|---|
| 유형 | 논글로벌 (Standard+Close, 바텀바 숨김; 실제 라우트 아님) |
| 과업(동사) | 보유한 블루 캡의 장착 상태와 가능한 행동을 구별한다 |
| 목적 | 같은 아이템이 보상 미리보기와 보관함에서 다른 정보 슬롯을 갖게 한다 |
| 주연 1개 | 블루 캡 O-ITEM 보관함 표시 |
| 대표 행동 1개 | 닫기(시연은 비기능·장착 저장 없음) |
| 핵심 데이터 | 동일 블루 캡 Media/Identity, 예시 Owned/Equipped State, 비기능 장착 Action 설명 |
| 보조 데이터 | 보상 미리보기 비교 예 |
| 다른 화면 책임 | 실제 경제·장착·구매는 제품 로직 범위 밖 |
| 제외 목록과 이유 | 새 글로벌 Route, 실제 구매·장착 버튼 동작, 가격·보상 확정 신호는 허위 동작 위험으로 제외 |

**G1:** 주연 1개/대표 행동 1개/제외 목록 확보. 구현 후 첫 뷰포트 실측으로 재판정한다.

## 02 콘텐츠·행동 인벤토리

- 좌측 비교: 공동 보상 미리보기 Media+Identity+조건, no price/equip.
- 우측 비교: 보관함 Media+Identity+Owned/Equipped, Action 의미만 비기능으로 표시.

**G2:** 데이터 중복은 같은 수치가 서로 다른 맥락에서 쓰일 때만 허용하며 실제 화면에서 횟수 검사한다.

## 03 객체·정보 구조

- 같은 C-IMAGE 실제 blue cap 에셋을 두 맥락에 사용. 슬롯 필수·금지 표는 O-ITEM 정본 참조.
- 대표 타깃 1개와 독립 행동 최대1개, fixture에 실제 지급·장착 상태 동기화 없음.

**G3:** O-ITEM/O-PROGRESS/O-PERSON-ACTIVITY 슬롯과 대표 클릭 대상 및 독립 행동을 검증한다.

## 04 선택·배제 근거

- 채택 O-ITEM의 다른 맥락 Variant/C-IMAGE contain. 배제 '모든 ItemCard 동일 슬롯', 실사용 Route, 가짜 구매/장착 성공.

**G4:** 모든 핵심 표현에 대해 채택과 배제 후보를 함께 기록한다.

## 05 시각 위계

- O-ITEM 실제 텍스트·이미지 크롭·상태가 양쪽에서 명확히 다르게 보이고, 실제 동작하는 CTA처럼 오해를 주지 않아야 한다.

**G5:** 390×844 첫 뷰포트 실제 Chromium 위치 및 보조 대비로 판정하며 단순 스타일 선언은 통과 근거가 아니다.

## 06 구현·회귀

- 별도 qa HTML이며 app.js routes/DB 변경 없음. Close는 문서상 목적만 재현하고 실사용 스택을 변경하지 않는다.

**G6:** 공통 토큰, 바텀바, 모든 기존 버튼·탭·응원·초대·마스코트 조합을 실제 실행한다.

## 07 검증·반례·복귀

- **현재 상태: 구현 전 설계 기록**. G1~G6은 설계 후보이며 구현 성공이라고 단정하지 않는다. 렌더/계산스타일/인터랙션 결과는 P3 Actions 실행 후 기록.
- G7 판정 축: 실행 / 규격 / 객체·조합 / 목적 / 행동·회귀.
- 실패 발생 시 실패한 Gate로 복귀한다. 실기기 Android·TalkBack·실제 A2 아트는 범위 밖이며 미검증.
