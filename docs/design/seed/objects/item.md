# O-ITEM · 맥락별 슬롯 조립

## 현행 계약

| 맥락 | 필수 슬롯 | 선택 슬롯 | 금지 슬롯/행동 | 대표 클릭 |
|---|---|---|---|---|
| 보상 미리보기 | Media, Identity, 획득 후보로서의 맥락 | 실제 조건·수량(Value), 실재하는 상세 Action | 구매 가격·장착 암시 | 상세 존재 시 한 개 링크 |
| 상점 | Media, Identity, 확인된 가격/통화(Value), 구매 가능 State | 실제 구매 또는 상세 Action | 장착 정보 자동 삽입 | 구매/상세 중 하나 |
| 보관함 | Media, Identity, 실제 보유·장착 State | 현재 선택·장착 Action | 구매 가격 반복 | 선택/상세 중 하나 |
| 꾸미기 선택 | Media, Identity, 선택·장착 State 구별 | 소유 정보·실제 장착 Action | 보유 미확정인데 착용 표시 | 선택/장착 중 하나 |
| 획득 결과 | 획득 사실 State, Media, Identity | 수량·다음 Action | 일상 아이템 목록 메타 반복 | 확인 한 개 |

**배치:** Grid는 미디어·이름·값을 규칙적 행열로 비교할 때. Rail은 가로 방향 다음 아이템 존재를 암시하고 가로 스크롤 가능할 때. List는 가격·이름·상태·설명이 주연이며 Flat Row가 필요할 때. **200% 확대에서 Grid 열 수는 줄이고 이름·상태를 생략하지 않는다.**

**C-IMAGE**는 크롭/컨테인/이미지 실패, **C-CREDIT**는 숫자+통화, **C-RARITY**는 등급 표현, **C-TEXT**는 이름·값·상태 의미 역할. O-ITEM은 슬롯 순서·관계·클릭 소유만 규범화한다. 미디어와 Identity/Value/State는 여백만으로 분리 가능하며 선과 다른 배경색은 필수가 아니다.

**상태 의미 우선순위:** 실제 장착 > 실제 보유 > 화면 내 선택 > 잠금/미확인. 보유와 선택은 같은 상태가 아니다. 예시 가격·장착 정책은 제품 확정이 아니므로 Fixture에는 **시연용** 표기를 한다. 이미지가 없을 때 이름·가격은 유지한다.

**반례 R-02 (image4):** 파란 캡·헤드셋·비니 3개가 정적 어두운 타일 안에 그림과 작은 글자만 있다. 상점인지 보관함인지 획득 후보인지 모호하다. 이름을 키우는 수정만으로는 부족하며 맥락별 필수 State/Value/Action을 정해야 한다.

**반례 R-08:** 큰 상자는 비클릭인데 작은 '보상 구성' 링크가 두 개 있다. 큰 물체의 클릭 기대와 실제 hit target이 불일치. 링크를 중첩하지 말고 전체 면의 시각적 클릭 암시를 낮추거나 대표 타깃을 명확히 한다.

## 이력
