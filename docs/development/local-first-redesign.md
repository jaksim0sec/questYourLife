## 구조와 실제 동작

- `ui/redesign/PatchDesign.kt`: 색상·간격·타이포그래피와 공통 표면/버튼/시트. 기존 VisualKit 테마 값을 재사용한다.
- `DailyQuestApp.kt`: 공통 제목/알림/메뉴, 홈·퀘스트·DM·클랜·마이 5탭, 전역 시트, 기존 세부 화면 경로. 선택 색상 전환, 채움/윤곽 아이콘, 시스템 인셋을 공통 처리한다.
- `HomePage`, `DmPage`, `ClanPage`, `ProfilePage`: 전역 틀 아래의 개별 콘텐츠. 개인 캐시·주간 기록·수행량은 실제 Room 데이터다. 가상 친구/기여도와 개인 기록은 구분한다.
- `CompanionGateway`: 화면이 의존하는 교체 가능한 서비스 계약. 현재 `LocalCompanionGateway`를 ViewModel에서 주입한다. 향후 서버 구현으로 교체할 때 메시지/계획/적용 의미를 유지한다.
- `LocalPlanTemplates`: 일본어·운동·독서용 제한적인 오프라인 세트와 일반 목표 가이드. 실제 AI 호출이 아니며 UI에 로컬 도우미로 표시한다. 마지막 목표의 시간 조절 제안도 새 초안으로 만든다. 기존 목표를 자동 수정하는 기능은 아직 없다.
- `CompanionDao`: 메시지·계획 초안을 영속 저장한다. 계획 적용은 하나의 Room 트랜잭션에서 목표/단계/첫 일일 실행/적용 표식을 저장한다. 같은 초안을 재탭해도 중복 생성하지 않는다.
- 클랜/친구는 교체 가능한 데모 응답이다. 친구에게 쓴 메시지는 기기에 저장되지만 실제 사람에게 전달되거나 가짜 실시간 답장이 오지 않는다. 실제 클랜 가입/순위/상자 수령 API는 없다.

## 개인 데이터와 퀘스트

Room v3 → v4는 기존 모든 테이블을 보존하면서 메시지 테이블과 일일 퀘스트의 종료/부모 연결 필드만 추가한다. v1/v2 경로도 기존 마이그레이션에 연결한다. 파괴적 마이그레이션은 사용하지 않는다.

로컬 대화에서 계획을 확정하면 목표와 실행 단계를 생성하고 첫 일일 퀘스트를 제공한다. 수락·완료 후 캐시를 한 번 지급하고 부모 단계를 함께 반영한다. 연결된 부모 단계 자체의 캐시는 0이므로 같은 행동의 보상이 중복되지 않는다. 상세에서 직접 단계를 완료해도 연결된 일일 실행과 보상을 함께 확정한다.

완료하지 않은 지난 실행은 오늘로 이어진다. 내일로 미루기는 항목 복제 없이 예정일을 옮긴다. 그만하기는 기록을 남기고 현재 목록/알림에서 제외한다. 부모 목표는 유지하며 이후 날에는 같은 단계의 새 제안을 받을 수 있다. 같은 날 같은 목표의 다음 단계를 자동으로 계속 쏟아내지는 않는다. 남은 일일 분량 안에서 목표의 다음 실행을 준비한다.

주간 표시는 Asia/Seoul 월요일 기준이다. 마이/클랜/기록에서 연결된 일일 완료와 부모 단계를 한 행동으로 센다. 보유 캐시와 주간 획득 캐시는 서로 다르며 구매가 주간 성취량을 줄이지 않는다.

## 이번 단계에서 남긴 작업

- 퀘스트 목록·목표 상세·꾸미기는 기존 작동 화면을 연결했다. 챕터/메인 계층의 재설계, 접기/펼치기, 사용자 편집과 새 디자인 전환은 후속 작업이다.
- 실제 AI 상담, 기존 목표에 대한 대화 기반 수정·수동 단계 편집, 로그인/동기화, 온라인 친구/클랜/랭킹, 상자 수령은 미구현이다.
- 조건형 걸음/위치 퀘스트, 완료 취소와 재화 역거래는 후속 작업이다.
- 고해상도 마스코트/착장/상자 에셋은 새로 생성하지 않았다. 기존 작은 자산은 아바타 정도로 사용한다. 착장·상자 연출을 본격 구현하기 전에 사용자에게 필요한 원본 에셋을 요청한다. 시연 이미지를 잘라 버튼이나 보상 그림으로 사용하지 않는다.
- 이 변경은 디자인과 개별 기능의 기반 1차 구현이다. 전체 시연 재현이나 모든 페이지 개편 완료를 뜻하지 않는다.
