# 현생패치 · 하단 네비게이션 개발안 (초안)

> 상태: **Draft / 미확정** · 작성일: 2026-11-01  
> 목적: 기존 네비게이션의 저품질 문제를 근본적으로 재설계할 **개발 기준 기록**  
> 범위: **하단 4탭의 레이아웃·아이콘·전환 경험만**. 이 문서 작성 단계에서 코드/앱 동작 변경 없음.

## 1. 배경과 문제

실기기 화면과 사용자 참고 영상(Cuts, 치지직, 토스) 및 시안 비교에서 확인된 문제:

- 아이콘들이 서로 다른 규격/스타일로 보임. 특히 **아이콘 굵기·크기·실루엣·시각적 무게**가 불균형함.
- 아이콘과 라벨이 지나치게 떨어져 있고, 라벨 크기·기준선·수직 위치가 어색함.
- 4개 탭이 독립적으로 떠 보임. 상단 콘텐츠와 구분되는 **하단바 전체의 균형**이 부족함.
- 활성 상태가 색상 변화에 과도하게 의존하고 누르는 순간의 응답/전환 연결이 약함.
- 이전 수정은 크기와 색만 계속 바꾸는 방식이어서 실기기에서 시안 품질을 얻지 못했음.
- 빌드 성공을 디자인 검증 완료로 오인했던 절차상 문제도 있었음.

## 2. 목표

**“네비게이션을 의식하지 않고도 정확하고 기분 좋게 이동하는 경험”**이 우선이다.

- 참고 앱에서 **원리(즉시 반응, 아이콘 일관성, 전환 리듬, 정보 밀도)**만 학습. 해당 브랜드의 아이콘/화면을 복제하지 않는다.
- 현생패치의 크림·오프화이트 배경과 스탬프 레드를 유지하되, 네비게이션 자체는 절제한다.
- 홈 / 퀘스트 / 기록 / 꾸미기 **기존 4개 목적지 유지**. 메뉴 구조 변경 없음.
- 퀘스트·데이터·알림·보상 계산·Room·APK 설정은 변경 대상이 아님.

## 3. UI 구성 규칙 (초기 제안, 실기기 조정 전)

| 항목 | 초안 기준 |
| --- | --- |
| 배치 | 동일 너비 4등분, 아이콘-라벨 수직 정렬, 중앙선 정확히 일치 |
| 탭바 높이 | **약 60~68dp**(시스템 내비게이션 인셋 제외), 내용에 따라 조정 |
| 아이콘 | **약 22~24dp**, 단일 아이콘 계열·공통 stroke·동일한 시각적 무게 |
| 라벨 | **10~12sp** 정도, 짧고 또렷한 한국어, 동일 기준선 |
| 아이콘↔라벨 | **약 4~6dp**. 과하게 멀리 떨어뜨리지 않음 |
| 터치 영역 | 탭 전체 클릭, 최소 **48dp** 높이·충분한 너비 |
| 활성 상태 | 스탬프 레드, 아이콘 상태 변화(채움/윤곽 또는 자체 선택형), 텍스트 강조 |
| 비활성 상태 | 가독성 확보한 중립 회색, 다른 탭과 정확히 동일한 톤 |
| 배경 | 따뜻한 크림/오프화이트, 경계선이나 그림자는 필요한 경우에만 매우 약하게 |
| 선택 배경 | 기본값은 **없음**. 큰 타원·필·과도한 글로우를 습관적으로 넣지 않음 |

수치와 정확한 색상은 **고정 스펙이 아니라 출발점**. 실제 삼성 기기 캡처로 비율을 검증한 뒤 확정한다.

## 4. 인터랙션/모션

1. **터치 즉시:** 아이콘·레이블이 곧바로 선택 상태에 반응한다. 네트워크나 화면 데이터 로딩에 묶지 않는다.
2. **선택 반응:** 약 **120~180ms**의 부드러운 색·아이콘 상태 전환. 필요한 경우 극히 약한 scale(예: 0.96→1.0). 튀어오르는 스프링이나 큰 이동은 기본값에서 제외한다.
3. **콘텐츠 전환:** 탭바 위치·높이는 고정. 본문만 짧은 페이드/상태 복원 처리하며, 불필요한 전체 페이지 슬라이드나 화면 깜빡임을 피한다.
4. **재선택:** 현재 탭을 누른 경우 화면 재생성·스크롤 초기화·DB 재호출을 일으키지 않는다. 최상단 이동 같은 별도 동작은 추후 합의.
5. **로딩:** 로컬 데이터가 즉시 준비되면 스켈레톤을 억지로 표시하지 않는다. 로딩이 필요한 화면에서만 레이아웃 이동이 없는 상태 UI를 사용한다.
6. **접근성:** 시스템 '애니메이션 줄이기' 설정과 스크린리더 탐색을 고려한다. 탭 이름 및 선택 여부를 전달하며, 색 외의 구분도 제공한다.

## 5. 구현 구조 (계획만)

- 기존 Kotlin + Jetpack Compose 기반 유지, 네비게이션에 필요한 상태와 화면 전환 책임을 명확히 분리한다.
- 공통 아이콘 에셋을 **같은 크기·stroke·viewBox 체계**로 관리한다. 아이콘 소스는 최종 비교 후 선정/제작. 초안 단계에서 새 이미지·의존성 추가 없음.
- 탭바는 화면마다 재생성하지 않는 공유 UI로 구성하며, Android 시스템 내비게이션/제스처 영역은 **WindowInsets**로 처리해 이중 여백과 겹침을 방지한다.
- 탭 간 상태(스크롤 위치·필터)를 재진입 시 보존하고 중복 탭 이벤트로 불필요한 재구성을 피한다.
- 화면 애니메이션과 탭 선택 애니메이션의 타이밍을 별도로 관리하되 두 시스템이 경쟁하지 않도록 한다.
- 기존 로직과 직접 결합하는 대규모 재작성 금지. **하단 네비게이션만 독립적으로 검증** 후 다른 화면에 반영한다.

## 6. 작업 순서 / 완료 기준

| ID | 작업 | 완료 기준 | 의존 |
| --- | --- | --- | --- |
| NAV-01 | 참고 영상·실기기·시안 나란히 비교 | 아이콘 크기/배치/활성 상태/전환 방식의 차이 명세 | 없음 |
| NAV-02 | 4개 아이콘 계열 통일 | 활성·비활성 두 상태 모두 같은 스타일·무게 | NAV-01 |
| NAV-03 | 탭바 레이아웃 재작성 | 4등분 정렬, 적절한 높이, 글자/아이콘 간격, 시스템 바 불간섭 | NAV-01~02 |
| NAV-04 | 탭 선택·화면 전환 연결 | 탭은 즉시 반응, 콘텐츠만 자연스럽게 전환, 탭 상태 유지 | NAV-03 |
| NAV-05 | 실기기 및 회귀 검증 | 홈/퀘스트/기록/꾸미기 전환, 글자 확대·제스처 모드·뒤로가기 검증 | NAV-04 |
| NAV-06 | 시안 대비 최종 조정 | 나란히 캡처하여 눈에 띄는 비율·두께·간격·전환 차이 해결 | NAV-05 |

**합격 판정 조건:** Android 빌드 성공만으로는 완료가 아니다. 동일 기기에서 *정지 화면 + 실제 탭 이동 영상*을 확인하고, 기존 메뉴 기능·선택 상태·스크롤 복원·터치 피드백이 정상이어야 한다.

## 7. 범위 밖 / 미결 사항

- 전체 홈·퀘스트 화면 재설계, 신규 보상, 서버 동기화, 새로운 네비게이션 탭 추가는 **이 작업 범위 밖**.
- 아이콘의 최종 제작 방식(VectorDrawable/Compose Vector 등), 선택 표현의 미세 디테일, 정확한 dp/sp 수치는 레퍼런스 비교 후 확정.
- 탭 재선택 시 최상단 이동 여부와 하위 화면에서 탭바 숨김 규칙은 구현 전 별도 결정.
- 문서만 생성하는 현재 단계는 **NAV-01~06 모두 미착수**. 구현·빌드·실기기 검증 완료로 표시하지 않는다.
